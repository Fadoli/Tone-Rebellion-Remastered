# Unites, panneaux de lieu et deplacement

## Observations et port

### Panneaux de lieu

- `FUN_0046466f` attribue un hall initial par joueur et crée quatre floaters. Les lignes `pwork`, `swork`, `mwork`, `lwork` de `floater.txt` donnent une vitesse 3; `FUN_00462a87` appelle `FUN_00466fe4` pour les initialiser. Cette dernière fixe le niveau à 0, la charge à 0 et les HITS courants à `FUN_00420f28` (maximum). Pour les quatre entrées `*work`, `floater.txt` donne 3 HITS et 0 en force; `FUN_0041fde6` calcule la force affichée. Le panneau de `FUN_0044338b` affiche pour un travailleur standard les libellés `WORKER`, `HITS current/max` et `STRENGTH`; sa branche worker n'affiche pas `LEVEL`. Le remake initialise ces champs sur chaque ouvrier de départ et les lit dans son pane `IWLocInfo` pour afficher les PV et la force courants, au lieu de figer ces valeurs dans le dessin. XP n'est pas affiché dans cette branche source. Les ordres directs restent réservés aux classes que le code original accepte; les contrôles prototypes de worker ont été retirés du code et de l'exécutable.

- **Observation :** `FUN_0044338b` n'affiche `CHARGE` que si le lien floater `+0x0c != -1`; numérateur = short `+0x22`, dénominateur = `floater.txt` row `+8` via les clés `+0/+4` (`ev_995b04cc8ed7dc755e49489cf97d7e86bafd66996c26c5275f6e61b4af808b7f`, `ev_400be7fc416e3e48c58ebeae7f1497639f909f0569891b58d5b3cba579bbab2a`, `ev_055bd9354dfe4717f5f4c2749565d4303a049541ad9fbd7afe7d37d0536bc244`). `FUN_00466fe4` initialise le compteur à zéro; `FUN_0041e569`, `FUN_004200d2` et `FUN_00420188` le modifient (`ev_0ca802ac15043c61c073f6d68546619fc924a4ba10fd4d9f04e203668dc62ed7`, `ev_6c3ec9c58f2e2ec6ef837d8737ba3dfece6d35c11a918338523e688a6746c25a`, `ev_ad5590e5bdd229ea3ac351753a2221b9d2393fc5bb358b9f475119209abbe728`, `ev_f961a5617f0ea77c8f7d5f211856963862326a35ce98f1af89be81e70cd5c196`). Les floaters initiaux gardent `+0x0c = -1`, donc leur fiche saute cette ligne (`ev_a5f6ff6cbb1d9a1b23aa8807337444803e3415de869ec691acf503f150bb3523`, `ev_352feb8e600eceb96c53f7813bd012e104389976cd0dc42358a78b6a0fcddd24`).

- **À ne pas confondre :** le byte `+0x22` du record d'île (pas `0x60`) est un masque d'éligibilité; le compteur CHARGE est le short `+0x22` d'un record floater (pas `0x4c`). Le modèle porte ces deux champs séparément.

- Le remake stocke maintenant le lien `+0x0c` et le compteur `+0x22` initialisés des ouvriers, puis n'affiche `CHARGE` que si ce lien est actif. Les ouvriers initiaux gardent le lien `-1`, donc leur fiche n'ajoute pas la ligne. L'affectation du lien et les transitions de charge restent à porter; le bâtiment sélectionné garde `BLDNAME`, sprite et `LEVEL`.

**BLDNAME index — observation and port:** `FUN_0044338b` computes `record[+0x10] - 0x25 + record[+0x14] * 16` (`ev_995b04cc8ed7dc755e49489cf97d7e86bafd66996c26c5275f6e61b4af808b7f`). `FUN_004641de` resolves player-specific pad IDs by adding `16 * player` (`ev_f92b05e1bac76d2be3a91b76e6eb420474e1d04db600d49cc8d4a55edf30587d`). The remake already stores that player-specific ID in `record_value_10`, so its `runtime_item_id - 0x25` lookup is equivalent; adding owner again would be wrong. The building pane shows `BLDNAME`, sprite and `LEVEL`; source `CHARGE` concerns a linked floater, not a site.

- **Roster `IWLocInfo`.** `FUN_0044034e` prépare six slots pour le contexte joueur d'un objet de classe 0; `FUN_00440567` les dessine et `FUN_00440451` sélectionne le premier slot occupé dans une zone stricte de ±15 px. Les ancres normales viennent de `0x4a0498/0x4a04a8`; l'ID `0x2f` utilise `0x4a04b8/0x4a04c8`. Evidence : `ev_9ef02eb58bdf8a0866dbfbc4fddb24eb95a3c0322ffbf1e75b23988cc0c84e8d`, `ev_cb0962ae9a0187897045bd9eabf82039d7325297fa191f029a6c7d4a5a3e33ed`, `ev_9e5f61cf79edd2a0425ee2f8b0f8c237a37b466f2219e936bdc3427204f308c2`. Le remake porte les deux géométries et affiche/sélectionne ses quatre ouvriers initiaux au Hall, en gardant le lieu courant. Limites : niveaux/classes ultérieurs et effets complets de `FUN_0042704b` non portés; pas de capture comparative.

- **Population du Hall.** `FUN_0046562b(type,-1)` compte les records actifs dont le premier dword égale `type`; `FUN_00440567` affiche ce total sous `POPSTR`. L’allocateur initialise ce dword avec le type demandé (`ev_fd7d84c3c921f63a87acb8c96ced7eaf23eb105f65c68340e3953e66ed`, `ev_0ca802ac15043c61c073f6d68546619fc924a4ba10fd4d9f04e203668dc62ed7`). Au démarrage `FUN_0046466f` demande quatre unités subtype 0 par type 0–3 (`ev_ac313cb8cc73f9c102676395cd14cb97b5b1f9355d074df1e6656ce028d2d36f`). Le remake rend `POPSTR` et `WORKSTR` depuis son registre initial simulé; la création ultérieure d'unités reste incomplète.

- `FUN_004337d9` reçoit les événements d'île. Sur les événements souris 6/7 et hors de certains modes UI, il délègue à `FUN_00435826`; ce dernier émet le message sélection `0x3f` sur une cible floater. Son chemin qui émet un déplacement `0x4c` est conditionné par le bit `0x4` de l'état UI `+0x178` (`ev_5fabac375596d1e1457b7649fb698b76bf3f96b23dab00f021e899fcd4d2c1f2`). Le message passe par `FUN_0042970c`, qui sélectionne selon son champ `+0x48` entre dispatch direct (`FUN_0046c402`), dispatch secondaire (`FUN_0046c1b4`) et file locale (`FUN_0046c3bc`) (`ev_bcb9a925483956dd92de831e72742c3a6510dbd9a56729b017c9c5223fe5c3a5`). `FUN_0046c402` appelle indirectement le gestionnaire du contexte actif depuis un tableau de slots à pas `0x130` (`ev_5d7372e111e8a989a1bad601deacda8478942b76678d4c0f95271ab98899581f`). Cette preuve établit le mode requis et la route du message, mais ne révèle pas le callback effectif ni son garde de classe/état; elle ne permet donc pas encore d'activer le déplacement des soldats/mages, et ne prouve pas que les ouvriers l'acceptent. Les commandes manuelles de worker et raccourcis ressources ont été retirés du source et de l'exécutable racine.

- **Contrôles de déplacement — observation et port.** Au clic gauche, `FUN_0044003d` délègue le hit-test de six ancres à `FUN_00440451`; un slot occupé émet `0x3f(ID)`, sinon `0x32` si `+0x18 != -1`. `0x32` atteint conditionnellement `FUN_0042fa0f` si le dispatcher général est en mode 0 et le callback actif au slot 3; l'état au clic n'est pas établi. Au clic droit, le code émet `0x4d(propriétaire,0)` si le propriétaire diffère du joueur, puis `0x3d(1,1)`. **Chemin `0x3d` :** `FUN_0042fa0f` appelle `FUN_0046c371(DAT_005c37e4[1],0x35,...)`; le wrapper rejette si l'état courant `+0x29f2` est négatif, sinon invoque indirectement la méthode d'offset vtable `+4`. La valeur runtime de l'entrée, la cible virtuelle et sa garde métier restent inconnues. Le dispatcher général `FUN_0042970c` (+0x48) est documenté séparément et ne suffit pas à résoudre cet appel. Le remake rend le contrôle et son infobulle; le roster Hall sélectionne les quatre ouvriers modélisés et garde le lieu sélectionné. Le déplacement n'est pas porté. Evidences : `ev_dfa9260d630c5590f535d54281a0b8f2c2767e3ca99d4a00ffdd596b3104b7eb`, `ev_196d5ce18818030f061f610add4e421b67b51a08a81cfe4b30f91fd722d4a4dc`, `ev_1a06455495cb08c19a3e95bb1bd8abb4f5f2df731cdd09e809cc8c2a78f504f9`, `ev_94eb91d39af9704767219d6df99b523c4408544d37cebde8472793c068780572`, `ev_e485a0839f32ca445383d2eab74cff5f5c3744ea6dbfc9bfc1b3c00a0edaa26a`, `ev_a8230350584e54954217dfeda123b6cf8d9dc6ca7211fff2385661c22cdab6ba`, `ev_6ac7cc6650dc8a0e9b412c055606948d1c6dbbdd3e6c6df0a7fcc1551764419e`, `ev_f8a09cad809f94f6483fa8f6623537024026f2d86fdd3f36b90ed39dbda0bd65`, `ev_ed92b375145a0b030776f82d115ccc237230777746be74169b6aac305580d646`.

- **Contexte d'interaction d'un lieu — observations Ghidra.** Le handler d'île `FUN_004337d9` traite le message `0x4a` en envoyant un événement catégorie 3, sous-type 5, ou 6 selon que le champ de l'objet sélectionné `+0x10` est non nul ou nul (`ev_bf1a97d80227c0c4c2146750b4513c1bbd0abd3f4ac26efa9abb971e514ed100`). `FUN_00465793` route les sous-types 5 et 6 vers `FUN_0045f4f5` et `FUN_0045f5c5` (`ev_1f76cc3b29917d1eea5e2c9d8e198f5ff8f38c82262e70c19d78f258790854a4`). Le premier a des gardes d'éligibilité, débite trois champs de ressource, mémorise l'île et le lieu aux offsets joueur `+0x13ba/+0x13bc`, puis active `+0x13c0`; le second valide ce lieu mémorisé, peut restituer les ressources pour le même objet et efface le flag (`ev_e3fcf5ee68c5c2fd4dbca869bf24eb98222b431ac521b6829f9a7d85450564ba`, `ev_5e1fef42131f692cd0fa68f2573a3136ff69180f0640f446573af1d9f285312e`). Séparément, `FUN_0042fa0f` traite les messages `0x49/0x4a` par un sous-type 6; le chemin `0x49` rafraîchit aussi `IWLocInfo` et `IWLocControl` (`ev_ed75141a79f1bac30a4ad39dcad68e710e351330bcd3044aa3cb304ef2a796b2`). **Inconnue :** les pseudocodes examinés ne relient pas ces messages à un clic ordinaire de sélection de lieu ni à l'initialisation de la sélection au Hall. Ces événements ne suffisent donc pas à justifier la création d'un contexte courant par défaut dans le remake.

- **Barre d'île et TOGREALM.** **Observations :** `FUN_0042fa0f` inverse trois globals indépendants; `FUN_0042704b` associe le premier au badge royaume (`FLTINFO` 22–25), le deuxième à santé et états, le troisième à d'autres indicateurs. `FUN_0042822b` appelle le rendu monde avec overlays actifs; `IWLocInfo` les force temporairement. Le PE place les globals dans une région `.data` sans octets sur disque. **Interprétation :** le chargeur PE initialise cette région à zéro. Références : `ev_e237e172a682f09a34d6fa8f9a34f10489cf0ed25de76eb181a60037ef0e2a00`, `ev_ddb8e138af63022b4fe4afe350c82ee206aae295bebe6a8c7ac97191c1259c99`, `ev_cc0c96617a01a7e08e8a16aef2a339e38377c3144fcf754bcf5e3e741845de18`. **Port remake :** `TOGREALM` contrôle le badge royaume des quatre ouvriers initiaux; santé et état du monde restent en attente de leur modèle runtime. `PANIC` commute un bit différé; lecteurs inconnus (détails dans [les notes des panneaux](island-panels.md)).

- `FUN_00420991` (`ev_b758701979d34e447f00b2067f67d58c0c58d9b8c28b444e24dfd4a160713da5`) filtre des candidats d'affectation autonome selon classe/flags et table de niveau. Ce filtre ne confirme pas le garde de commande `0x4c`. Le noyau de déplacement du remake reste sans API publique d'ordre direct; le tick appelle maintenant `floater_motion_effective_speed` avec le contexte de chaque floater avant le pas de coordonnées. Les modificateurs dépendant des données de catégorie/site et les overrides near-target restent nuls tant que leurs sources runtime ne sont pas modélisées. **Déplacement Hall — observations Ghidra et port.** `FUN_00441d3e` (`IWLocInfo`, Evidence `ev_721b02ae62d9e81fff934679f3d0f672a102544ced812b19041e4d27311fc4f1`) traite l'événement 6 : après ses gardes, il envoie `0x48` si `+0x13c0` vaut zéro, sinon `0x4a`. `FUN_0042970c` route ces messages selon `+0x48` (Evidence `ev_bcb9a925483956dd92de831e72742c3a6510dbd9a56729b017c9c5223fe5c3a5`). Indépendamment, `FUN_00465793` route type 3/sous-types 5/6 vers `FUN_0045f4f5`/`FUN_0045f5c5`; le sous-type 5 vérifie le contexte, calcule et débite les coûts, mémorise île/lieu source et active `+0x13c0` (`ev_90fc7b398e8cc430ee898f0371c196e285bf0f21c5cd78aa04fcdd060294d4ce`, `ev_598cfe2b014b15e607c8b41ac943b5dd6af4e3db3c818406a1653591e00c406a`). **Inconnu :** aucune preuve ne relie le dispatch `0x48` à l'événement type 3/sous-type 5, ni n'établit que l'événement 6 vient de `IWMove`; `FUN_0042fa0f` associe séparément les noms `IWMove`/`IWHallMove` à `IWTextInfo` message `0x3039`, paramètres `(5,1)` (`ev_66dacbd51cf6785b063a74bf329239127645ce19926b671235f30adca57b2aea`). Le coût de base Hall dans `original_content/pad.txt` est `(15,0,15)`; `game_session_location_move_costs` porte le multiplicateur `+0x4a+1` et est testé (`ev_166ec7236cb49a5bd45dcbc859b69f029d1132243f92ee2e155015d72a50dedd`, `ev_f92b05e1bac76d2be3a91b76e6eb420474e1d04db600d49cc8d4a55edf30587d`). La sélection de cible reste à établir; le clic carte `0x4c` suit un autre chemin.

Le flux `IWLocInfo` 6 → grab/place est maintenant relié : `FUN_00441d3e` valide la source avec `FUN_0045f337(site,NULL)` avant `0x48`; `FUN_0042fa0f` émet alors la catégorie 3/sous-type 5. Le garde source exige un bâtiment appartenant au joueur; `PIT_Object` item 1 n'est admis que comme cible (site libre, visible, selector 5..33). Le sous-type 6 peut écrire l'objet tenu dans cette cible. Voir [interaction des objets posés](island-ground-object-interaction.md) pour les conditions, la copie source→cible et les limites; ce chemin ne prouve pas la collecte de l'objet item 1.

**`SURPFLOW` / `WORKSTR` — observation et port limité.** `FUN_00440567` lit `DAT_006191f8 + owner*0x14a0` pour `SURPFLOW`; `FUN_004526de` et `FUN_004672ef` lisent la même table comme garde. Les xrefs examinés sont des lectures; cinq slots statiques échantillonnés sont nuls. Écritures/initialisation restent inconnues (`ev_35dd32f9b0d9fd7b10dddf106f9517fe0eb352d969838552bc284f20e0c80c71`, `ev_785c735c398b2b79aed64f722b3b9dc00fbd787d8f894a5c1679744c01aad41c`). `WORKSTR` compte les floaters du type demandé, puis ceux de sous-type 0, et affiche `count0` ainsi que `int(count0*100/total)` (`ev_15c8370778d014104c360b1fc45e6174add31e7ce2b771b4a2f6eba9473c9fc0`, `ev_73b7a5d00a820cccc744dfd2168d1f0704c9ce37dda703814c69df8fc9be7ca5`, `ev_20c6e74d9bf368220195a9f1340f0eb4feaa54a95c1d25b61a49ebad099863ab`). `FUN_00466fe4` confirme que `+4` est le sous-type; `FUN_0046466f` crée quatre entrées initiales de sous-type 0 par type 0–3. Le remake affiche la formule sur les enregistrements simulés uniquement; il n’interprète pas les autres sous-types, le cas source `total=0` ni le sens métier de `WORKSTR` (`ev_0ca802ac15043c61c073f6d68546619fc924a4ba10fd4d9f04e203668dc62ed7`, `ev_ac313cb8cc73f9c102676395cd14cb97b5b1f9355d074df1e6656ce028d2d36f`).
