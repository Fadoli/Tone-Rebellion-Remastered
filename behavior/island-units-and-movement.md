# Unites, panneaux de lieu et deplacement

## Observations et port

### Panneaux de lieu

- `FUN_0046466f` attribue un hall initial par joueur et crée quatre floaters. Les lignes `pwork`, `swork`, `mwork`, `lwork` de `floater.txt` donnent une vitesse 3; `FUN_00462a87` appelle `FUN_00466fe4` pour les initialiser. Cette dernière fixe le niveau à 0, la charge à 0 et les HITS courants à `FUN_00420f28` (maximum). Pour les quatre entrées `*work`, `floater.txt` donne 3 HITS et 0 en force; `FUN_0041fde6` calcule la force affichée. Le panneau de `FUN_0044338b` affiche pour un travailleur standard les libellés `WORKER`, `HITS current/max` et `STRENGTH`; sa branche worker n'affiche pas `LEVEL`. Le remake initialise ces champs sur chaque ouvrier de départ et les lit dans son pane `IWLocInfo` pour afficher les PV et la force courants, au lieu de figer ces valeurs dans le dessin. XP n'est pas affiché dans cette branche source. Les ordres directs restent réservés aux classes que le code original accepte; les contrôles prototypes de worker ont été retirés du code et de l'exécutable.

- `FUN_0044338b` (`Iwloc.cpp`, evidence `ev_995b04cc8ed7dc755e49489cf97d7e86bafd66996c26c5275f6e61b4af808b7f`) peint le panneau `IWLocInfo` de l'objet sélectionné et son sprite. La branche floater affiche `HITS current/max` et `STRENGTH`; `FUN_004633a7` charge les 45 lignes ordonnées de `floater.txt`, et le lookup `FUN_00464242` choisit la ligne par les deux premiers champs du record sélectionné. Son quatrième nombre numérique (`row+8`) alimente aussi le dénominateur affiché sous `CHARGE`. Evidence du parse/stockage : `ev_e7f725f81eab46ea839a737e2792929e53f694dbe4f1f7479aca492f6425d2e9`; appel de chargement `floater.txt` : `ev_89d7b019a1136c82c5f536fd69c8a0fbe005f20d4f0c63e54cebbcec638fcd91`; colonne/clé CHARGE : `ev_72d523e1e6a74d3a8cb013544327ee317b5b912aaa5087c2c2a86bc98b12ba7b`, `ev_edef5d74d86a8602d13348a060d283c02aeecfe97df5189534463d784b6b7aa1`, `ev_c9bc0f3f9fe61faa8c63ebe1a81febc193e4a1a329bf125761e8439209065dde`. The local data labels this column `max attack points` (`C:\git\ToneRebellion_Raw\original_content\floater.txt`). The remake now parses this source table and initializes starting workers' HP, strength and speed from their type/subtype-0 rows. **Unknown:** these facts do not map the selected site's raw key fields (`+0`, `+4`) and mutable `+0x22` to `GameRuntimeLocation`; site `CHARGE` remains unported. The building pane still shows `BLDNAME`, sprite, and `LEVEL` only.

**BLDNAME index — observation and port:** `FUN_0044338b` computes `record[+0x10] - 0x25 + record[+0x14] * 16` (`ev_995b04cc8ed7dc755e49489cf97d7e86bafd66996c26c5275f6e61b4af808b7f`). `FUN_004641de` resolves player-specific pad IDs by adding `16 * player` (`ev_f92b05e1bac76d2be3a91b76e6eb420474e1d04db600d49cc8d4a55edf30587d`). The remake already stores that player-specific ID in `record_value_10`, so its `runtime_item_id - 0x25` lookup is equivalent; adding owner again would be wrong. Site `CHARGE` remains unported because its keys and mutable field are not mapped.

- `FUN_004337d9` reçoit les événements d'île. Sur les événements souris 6/7 et hors de certains modes UI, il délègue à `FUN_00435826`; ce dernier émet le message sélection `0x3f` sur une cible floater. Son chemin qui émet un déplacement `0x4c` est conditionné par le bit `0x4` de l'état UI `+0x178` (`ev_5fabac375596d1e1457b7649fb698b76bf3f96b23dab00f021e899fcd4d2c1f2`). Le message passe par `FUN_0042970c`, qui sélectionne selon son champ `+0x48` entre dispatch direct (`FUN_0046c402`), dispatch secondaire (`FUN_0046c1b4`) et file locale (`FUN_0046c3bc`) (`ev_bcb9a925483956dd92de831e72742c3a6510dbd9a56729b017c9c5223fe5c3a5`). `FUN_0046c402` appelle indirectement le gestionnaire du contexte actif depuis un tableau de slots à pas `0x130` (`ev_5d7372e111e8a989a1bad601deacda8478942b76678d4c0f95271ab98899581f`). Cette preuve établit le mode requis et la route du message, mais ne révèle pas le callback effectif ni son garde de classe/état; elle ne permet donc pas encore d'activer le déplacement des soldats/mages, et ne prouve pas que les ouvriers l'acceptent. Les commandes manuelles de worker et raccourcis ressources ont été retirés du source et de l'exécutable racine.

- **Contrôles de déplacement — observation et port.** Au clic gauche, `FUN_0044003d` délègue le hit-test de six ancres à `FUN_00440451`; un slot occupé émet `0x3f(ID)`, sinon `0x32` si `+0x18 != -1`. `0x32` atteint conditionnellement `FUN_0042fa0f` si `FUN_0042970c` est en mode 0 et si le callback actif est le slot 3; ces états ne sont pas établis au clic. Le traitement reçu dépend ensuite de l'objet sélectionné. Au clic droit, le code émet `0x4d(propriétaire,0)` si le propriétaire diffère du joueur, puis `0x3d(1,1)`. `FUN_0042970c` route selon son mode (+0x48) vers un callback actif, un dispatch secondaire ou une file locale. Pour le `0x3d`, `FUN_0042fa0f` demande à `ISLEVIEW` la méthode `0x35`, mais le slot et sa méthode virtuelle ne sont pas identifiés; l'effet du clic droit reste donc inconnu et n'est pas porté. Le remake rend le contrôle et son infobulle; le roster Hall sélectionne les quatre ouvriers modélisés et garde le lieu sélectionné. Le lien de `0x48`, le coût et l'activation du déplacement, ainsi que la correspondance des IDs runtime avec le roster restent ouverts. Evidences : `ev_dfa9260d630c5590f535d54281a0b8f2c2767e3ca99d4a00ffdd596b3104b7eb`, `ev_196d5ce18818030f061f610add4e421b67b51a08a81cfe4b30f91fd722d4a4dc`, `ev_1a06455495cb08c19a3e95bb1bd8abb4f5f2df731cdd09e809cc8c2a78f504f9`, `ev_94eb91d39af9704767219d6df99b523c4408544d37cebde8472793c068780572`, `ev_e485a0839f32ca445383d2eab74cff5f5c3744ea6dbfc9bfc1b3c00a0edaa26a`, `ev_a8230350584e54954217dfeda123b6cf8d9dc6ca7211fff2385661c22cdab6ba`, `ev_6ac7cc6650dc8a0e9b412c055606948d1c6dbbdd3e6c6df0a7fcc1551764419e`, `ev_f8a09cad809f94f6483fa8f6623537024026f2d86fdd3f36b90ed39dbda0bd65`.
