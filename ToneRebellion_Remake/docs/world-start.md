# World start and initial simulation

## Initial game-world setup

The portable core has `game_start_assign_locations`, grounded in `FUN_0046466f`: normal mode assigns the four player slots to island indices 0–3, chooses a class-1 marker (`tone`) by its source-row ordinal (first for even slots, fourth for odd slots), then selects the nearest eligible class-0 location using the original Chebyshev metric from `FUN_004672a6`. Equal distances keep the first source row. It also reproduces the horizontal camera bounds, the raw initial pad argument `0x2a`, and four floater creation parameters at the marker. `FUN_004641de` resolves that argument per player as `0x2a + 16 * player`, yielding `p-hall`, `s-hall`, `m-hall` and `l-hall`; `game_session.c` now stores these resolved runtime item IDs. Alternate mode's island and marker-index rule is implemented as it appears in the pseudocode.

`tone_rng.c` implements the shared 15-bit LCG from `FUN_00474b90` and bounded scaling from `FUN_00467260` (`random × range / 32768`, truncating toward zero). The Win32 menu's visual randomness now uses this core helper. `tone_rng_unit` checks the observed output sequence and bound scaling.

`game_start_distribute_tones` ports marker/item selection from `FUN_00464b9e`/`FUN_004535e4`: first/last markers on islands 0–3, optional opposite marker in alternate mode, random selection from the first five markers on later islands, and IDs 6–9 constrained by two shape-ID tables. Its balance calculation follows the runtime reset in `FUN_004500c4`: parsed `+0x10` values persist only on class 3; prior placements in the current distribution also count. The home-island index corresponding to `DAT_006136b0 - 1` remains an explicit parameter because the global's runtime initialization is unresolved.

`game_session_initialize` in `src/core/game_session.c` builds mutable runtime records for an entire selected world. It applies per-player hall item IDs, floater starts, marker item placements, class-2 state `2`, class-2-to-bridge neighbor matches from `FUN_00461859`, and both class-0 assignment loops visible in `FUN_004637fc` (`bridge_count` sites with value `+0x24 = 5`, then two shape-derived assignments per island except the last). The Win32 New Game action reads every island layout in the selected world from `TONE01.COB` and initializes this session before opening the map. The island view resolves runtime items through `pad.txt` and `bldinf.txt`, loads their SHP sheets, and composites the data-driven layers selected by `FUN_0040bf98`. The source animation fields are preserved per site; CHUG/GLYP tick from `FUN_00450a71`, while other counters await the game transitions that update them. `FUN_0040ab42` is not used as a generic building animator because `FUN_0046303b` binds it to `PADS`. Initial and recruited floaters use the tribe-specific body/leg sheets listed in `fltinf.txt` and `shapes.txt`; `FUN_0042704b` plus `shapeinf.txt` ground body frame 0 and legs hover frames 0–15. The remake advances that hover cycle with its 33 ms timer, while the original in-game phase remains unresolved. Automatic worker recruitment rules and the `fltbirth.wav` event are documented in [`worker-recruitment.md`](worker-recruitment.md). It also uses runtime bridge matches and reports the selected record's current item/owner/auxiliary values. An integration check builds world 0 from local `WORLDPOS.TXT` plus its original `ISLANDnn.TXT` records; it resolves seven islands, eight bridge sites and twenty class-0 assignments. `DAT_006136b0` is unresolved, so the Win32 path currently supplies explicit home-island index 0; it does not infer this from the tribe selection. The `DAT_0049c99c` branch remains a configuration flag, with random assignment disabled in the UI. Startup IDs `0x17`–`0x19`, exact whole-startup RNG stream, full entity side effects, and `FUN_00460460` recalculation remain unported. See `../world_start_distribution.md` for evidence and limits.

Selecting an initial worker opens the `IWLocInfo` status pane. Its `HITS current/max`, `STRENGTH`, and movement speed initialize from the type/subtype-0 row of `floater.txt`; the remake parses all 45 rows using `FUN_004633a7`'s ordering and `FUN_00464242`'s index rule. The four start rows currently provide 3/3 HP, strength 0, and speed 3. The source's worker branch does not display XP, so the remake does not add it. Selecting a building shows its name and level, and its layered sprite follows the full-scale `FUN_0044338b` draw call and pane-relative anchor; a core regression test locks down the `IWLocInfo` geometry. Workers remain inspection-only: no direct worker order is wired to the selection UI. See `TODO.md` for the remaining source-trace work.

### First resource delivery loop

Ghidra evidence identifies three Hall stock fields and shows that mode 2 queues deferred fill requests; the remake cycles the three Hall controls and creates/removes requests at the island tick under the observed guards. For producer IDs `0x25..0x27`, `FUN_00450a71` starts `PROD` while the active bit is set and no output is pending, advances the production counter to the catalog threshold, then stores output code 1/2/3 at runtime `+0x24` (`ev_42f2f9245939e039d5f3d185117501094fc590095774d6ab3a5a5a725b2871e7`). `FUN_00452ceb` confirms the exact producer IDs are shared across players; ownership is checked separately at `+0x14` (`ev_d7bd51ae9e46498dd3b0e34936ed83c13e3893a362ead516a8440789a48f1594`). The remake's production tick and source validator now follow those exact comparisons instead of offsetting IDs by player. It also ports the 20-tick pre-cycle cadence, active-building gates, the raw `+0x2c` retry timer, and the pending-resource marker; `FUN_004528ca` confirms that placement initializes the item, owner, counters and active flags (`ev_c9ba49c0d3ba17fec57912ff2bc78bb5b0ba0702064f4be8d8900ee1e4ce3a72`). Type-4 resource tasks collect local or remote producer output and credit Hall stock. `FUN_00420a55` keeps the ten nearest eligible sources and `FUN_0041e28e` computes normalized inverse-distance weights, compares one 0..999 roll against each weight in candidate order, and returns no source if no threshold matches. The remake now follows that selection rule (`ev_8cbbb89cf96f8cec18ab31fded50c934c328575c25039ff87bdd77fcf45866ed`, `ev_e0241e9f30e8ecd1d01dd44ecbe3a05f57adeb0abde98993bde806ce756b5a3a`). Exact player X bounds and the runtime visibility-index mapping remain partially reconstructed. Construction requests wait for the delivered Build Tone total to reach the catalog cost, then placement clears the site resource counters as the source initializer does. Starting balances, stock caps and some activation-budget preconditions still need source/runtime confirmation. Selecting an initial worker draws the source `IWLocInfo` fields `WORKER`, `HITS 3/3`, and `STRENGTH 0`; trained-unit panels and remaining order gates are tracked in [`TODO.md`](../TODO.md). Source evidence and function notes are in [`../FUNCTION_GUIDE.md`](../../FUNCTION_GUIDE.md) and [`../unknowns.md`](../../unknowns.md).

The Hall `IWLocInfo` summary draws its three stock rows, `SURPFLOW`, `POPSTR`, and `WORKSTR` at the coordinates observed in `FUN_00440567`. It has no Hall title or `LEVEL` field: those labels belong to the separate generic detail renderer `FUN_0044338b` and are conditional on `FUN_004207f2` finding a linked runtime floater (`+0x0c != -1`); they are not derived from the Hall's building ID. `SURPFLOW` is localized and appears at pane-relative `(5, 4)`, using the player's remaining maintenance capacity. `FUN_00440567` reads the same player `+0x40` field calculated by `FUN_0045e6d3` (`ev_cb0962ae9a0187897045bd9eabf82039d7325297fa191f029a6c7d4a5a3e33ed`, `ev_40029ca226cb3025b370307705f49a00c27de614f0bce2bbaee8d6771a69c66c`). Although `FUN_00462285` counts accessible class-1 Tone pools, that regional sum is provisional: the following x87 path in `FUN_00477599` replaces gross capacity with `0.5 × 20.0 = 10`. The routine subtracts active-building upkeep and owned floaters, then clamps the net `SURPFLOW` to zero. Glyph 13 discounts building upkeep by 15%. Evidence for the fixed-capacity correction: `ev_66cb53842ddc917343a561124e9249e2745d1f4c76ffb10bee5033e69d7adcaf`, `ev_5c61a836b4d02046478493f5a15e9727aa1bce237747fd23d47bf6ef3d95000f`.

Ghidra shows `FUN_00466ce2` calls `FUN_0041e569` for active floaters. State `0x0e` decrements its timer only on the exact-arrival result from `FUN_00422d27`; states `0x0f`/`0x10` use a Chebyshev arrival radius of 10, overridden by nonzero attack range from `FUN_00420721` except when order `0x14` forces radius 0. `src/core/floater_motion.c` ports the observed final coordinate step: near-target speed reduction, per-axis clamping, and source-tick parity. `FUN_00435826` emits selection message `0x3f` for a clicked floater. In coordinate mode `0x13`, it quantizes the map destination with `FUN_0041e3eb` and emits message `0x4c`; `FUN_0042fa0f` then packages the selected floater, island, and packed destination for the local command path (`ev_95774420460d008bd7b106d737076055364941285cbc3aa7d63368622935eca1`, `ev_3bf0ee7cf769af3d7f196ff7feba294b3f489beddddf1f1dd24044ebc2b66397`, `ev_6ac7cc6650dc8a0e9b412c055606948d1c6dbbdd3e6c6df0a7fcc1551764419e`). The remake wires right-click on the island map to this coordinate order and processes it in the simulation tick; same-player ownership is checked before assignment. `FUN_0043530b` sets coordinate mode without a subtype check (`ev_72e80596751dc2c6363ddc044f570048475545d3f20c910786a7ab80b9e833eb`). `FUN_004633a7` loads seven `floater.txt` fields into 14-byte records, while `FUN_00464242` resolves tribe/unit-class records; `FUN_00422d27` reads speed at `+0x0c`. `FUN_0046466f` creates initial units with class 0, and the four `*work` entries have speed 3.
