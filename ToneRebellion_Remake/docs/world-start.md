# World start and initial simulation

## Initial game-world setup

The portable core has `game_start_assign_locations`, grounded in `FUN_0046466f`: normal mode assigns the four player slots to island indices 0–3, chooses a class-1 marker (`tone`) by its source-row ordinal (first for even slots, fourth for odd slots), then selects the nearest eligible class-0 location using the original Chebyshev metric from `FUN_004672a6`. Equal distances keep the first source row. It also reproduces the horizontal camera bounds, the raw initial pad argument `0x2a`, and four floater creation parameters at the marker. `FUN_004641de` resolves that argument per player as `0x2a + 16 * player`, yielding `p-hall`, `s-hall`, `m-hall` and `l-hall`; `game_session.c` now stores these resolved runtime item IDs. Alternate mode's island and marker-index rule is implemented as it appears in the pseudocode.

`tone_rng.c` implements the shared 15-bit LCG from `FUN_00474b90` and bounded scaling from `FUN_00467260` (`random × range / 32768`, truncating toward zero). The Win32 menu's visual randomness now uses this core helper. `tone_rng_unit` checks the observed output sequence and bound scaling.

`game_start_distribute_tones` ports marker/item selection from `FUN_00464b9e`/`FUN_004535e4`: first/last markers on islands 0–3, optional opposite marker in alternate mode, random selection from the first five markers on later islands, and IDs 6–9 constrained by two shape-ID tables. Its balance calculation follows the runtime reset in `FUN_004500c4`: parsed `+0x10` values persist only on class 3; prior placements in the current distribution also count. The home-island index corresponding to `DAT_006136b0 - 1` remains an explicit parameter because the global's runtime initialization is unresolved.

`game_session_initialize` in `src/core/game_session.c` builds mutable runtime records for an entire selected world. It applies per-player hall item IDs, floater starts, marker item placements, class-2 state `2`, class-2-to-bridge neighbor matches from `FUN_00461859`, and both class-0 assignment loops visible in `FUN_004637fc` (`bridge_count` sites with value `+0x24 = 5`, then two shape-derived assignments per island except the last). The Win32 New Game action reads every island layout in the selected world from `TONE01.COB` and initializes this session before opening the map. The island view resolves runtime items through `pad.txt` and `bldinf.txt`, loads their SHP sheets, and composites the data-driven layers selected by `FUN_0040bf98`. The source animation fields are preserved per site; CHUG/GLYP tick from `FUN_00450a71`, while other counters await the game transitions that update them. `FUN_0040ab42` is not used as a generic building animator because `FUN_0046303b` binds it to `PADS`. Initial idle floaters use the tribe-specific body/leg sheets listed in `fltinf.txt` and `shapes.txt`; `FUN_0042704b` plus `shapeinf.txt` ground body frame 0 and legs hover frames 0–15. The remake advances that hover cycle with its 33 ms timer, while the original in-game phase remains unresolved. It also uses runtime bridge matches and reports the selected record's current item/owner/auxiliary values. An integration check builds world 0 from local `WORLDPOS.TXT` plus its original `ISLANDnn.TXT` records; it resolves seven islands, eight bridge sites and twenty class-0 assignments. `DAT_006136b0` is unresolved, so the Win32 path currently supplies explicit home-island index 0; it does not infer this from the tribe selection. The `DAT_0049c99c` branch remains a configuration flag, with random assignment disabled in the UI. Startup IDs `0x17`–`0x19`, exact whole-startup RNG stream, full entity side effects, and `FUN_00460460` recalculation remain unported. See `../world_start_distribution.md` for evidence and limits.

Selecting an initial worker opens the `IWLocInfo` status pane. Its `HITS current/max`, `STRENGTH`, and movement speed initialize from the type/subtype-0 row of `floater.txt`; the remake parses all 45 rows using `FUN_004633a7`'s ordering and `FUN_00464242`'s index rule. The four start rows currently provide 3/3 HP, strength 0, and speed 3. The source's worker branch does not display XP, so the remake does not add it. Selecting a building shows its name and level, and its layered sprite follows the full-scale `FUN_0044338b` draw call and pane-relative anchor; a core regression test locks down the `IWLocInfo` geometry. Workers remain inspection-only: no direct worker order is wired to the selection UI. See `TODO.md` for the remaining source-trace work.

Ghidra evidence identifies three Hall stock fields and shows that mode 2 queues deferred fill requests; the remake cycles the three Hall controls and creates/removes requests at the island tick under the observed guards. `FUN_00450a71` writes a pending output code at producer runtime `+0x24` when a `PROD` cycle completes for `P-BLDTON`, `P-CRYTON`, or `P-MAGTON`. The population count covers the four modeled starting floaters; future unit creation is not implemented, and starting stock balances remain unresolved.
