# Menu, map, and island UI

## Menu prototype

The island scene uses the exact pane split in local `windows.txt`: `ISLEVIEW` occupies `(0,0)`–`(639,319)` and `ISLETMP` occupies `(0,320)`–`(639,479)`. It draws the corresponding `ISLANDnn.SHP` panorama at y=0 and loads the race-specific `ISLETMP%d.SHP` template at y=320, following `FUN_0044964f`; site sprite drawing is clipped to the upper pane. Location hit testing uses the same scene coordinates. The inspection text is remake UI.

The island bar renders `IWRealm` and the four controls from `windows.txt`/`mainbut0.shp`. `GOTOMAP` returns to the map; `TASKLIST` toggles modes 0/2. `TOGREALM` flips three source flags: the first draws realm frames 22–25, and the second draws health frame `0x15−maxHP` for initial world workers. Other state/charge badges remain unported because their runtime fields are unmapped. Floater selection retains the selected location; realm adjustment uses its `0x10000/0x20000` flags when available. Initial location selection remains unresolved. `PANIC` queues the source type-3/subtype-0 toggle; its meaning is unknown and network buffering is not reproduced. Hall commands open their observed modes. Glyphs and Inventory use local masks/counts and source-backed layouts; acquisition and production flows remain incomplete. See [TODO.md](../TODO.md).

The menu reads and renders original title and new-game sprites from `TONE01.COB` using the observed 6-bit palettes and the RLE structure recovered from `FUN_00404770` / `FUN_00404b74`. It uses the panes in local `windows.txt` for title and setup buttons and the new-game shape families referenced by `FUN_0044ec5d`. The setup screen animates the original glyph and floater frame families and draws the three original orbital rings with the game's LCG for their randomized specks. Begin opens a first world-map view rendered with the original `MAPBACK` and `SMISLE` art and `MAINMAP.PAL`; bridge effects use the observed palette ramp and particle routine, with endpoint interpolation approximated. Static WORLDPOS pairs are not equivalent to active links: Ghidra shows a separate runtime flag table, a handler that sets its counted flags, and a later transition that clears them. The table's loaded-image bytes are zero, but its map-entry runtime state is unresolved. The remake still draws every static pair until that state sequence is understood. Detailed evidence and remaining fidelity gaps are in [GRAPHICS_RECONSTRUCTION.md](../GRAPHICS_RECONSTRUCTION.md).

Title-menu and New Game button hit routing now reads the named panes and `SENDMESSAGE` destinations from the parsed `windows.txt` templates; NewGameWin’s special animated-tribe and central-art hit logic remains class-specific. The parser preserves optional pane offsets and other optional descriptor fields. This does not yet instantiate the binary’s full window class hierarchy. The menu uses the original `BGOUTFNT.FNT` bitmap glyph masks and reads contextual French help text from `tonehelp.txt` in `TONE00.COB`. On the title screen, hovering over a menu control shows its help text and alternate button frame. On New Game, hovering over a tribe, world-size, difficulty, exit, or begin control displays the corresponding short localized caption from `NEWGAME0`–`NEWGAME7` in `gamey.txt`, centered in the lower strip. It also reads the paired tribe lore entries from `newgame.txt` and shapes/justifies each line along the circular center opening, following `FUN_00428baa` and its `FUN_0044e613` bounds callback. The current text bottom anchor is y=392; all eight local French paragraphs pass layout checks against the original bitmap font, while the original text-height call remains unresolved. Clicking any animated tribe glyph changes the tribe and lore. Clicking the center art changes difficulty or world size in the small hit regions recovered from `FUN_0044e4f8` and `FUN_0044ebea`; the footer buttons remain available. It avoids clearing the visible viewport between frames, advances the floater at the original half-rate tick cadence, and plays the archive's `BUTTON.WAV` on mouse clicks. Ghidra shows `FUN_0041c46f` requesting `start` once at main-loop initialization and the title path requesting `ambi1`; the world-window/island transition code arms and consumes per-realm music using `tribe%d`, `act%d`, `levi` and a weighted random playlist. All 16 `tune` entries in local `sound.txt` map to WAV files under `C:\toneIso\THING2`; see [audio_inventory.md](../../audio_inventory.md). Effects such as `button`, `fltbuild`, and `levbuild` are separate WAV members in `TONE01.COB`; `FUN_00416a9a` chooses `levbuild` for owner ID 4 and `fltbuild` otherwise, and the remake now follows that owner condition after accepted placement. The remake now plays the one-shot `START.WAV` at launch, streams `ambi1` in menu/setup/map screens, and selects island music from the realm's `WORLDPOS.TXT` shape ID once per pending realm, using WinMM MCI playback. Looped music restarts when a one-second status poll observes that playback has stopped (the local waveaudio driver rejects MCI repeat). The `THING2` root can be set with `TONE_REBELLION_THING2`; the app also checks an adjacent `THING2` folder and `C:\toneIso\THING2`. Gameplay event effects remain unfinished.

Keyboard: Enter advances from title to setup, setup to the map, and the map to the selected island; with no map selection, it opens the chosen tribe's homeworld. N opens setup, Escape returns one screen, Left/Right change world size on setup/map and scroll the island panorama, D cycles difficulty, and 1–4 select tribes.

The world-size and five-value difficulty cycles match the `FUN_00448e5a` master handler; clicking the animated tribe glyphs follows `FUN_0044e4f8` and the tribe message path. On the map, hovering opaque island pixels displays the corresponding name from `names.txt`; clicking once selects an island and Enter or a second click opens it. Hit bounds and reverse draw-order hit testing follow `FUN_00405e11` and `FUN_00472013`. The island view loads the selected `ISLANDnn.SHP` panorama and palette, retains its `ISLANDnn.HZT`, parses `ISLANDnn.TXT` coordinates, and allows horizontal scrolling and location selection. `tone` locations render as animated Tone pools from `TONE.SHP`; the `smpad`, `mdpad`, and `lgpad` locations use their respective animation groups in `PAD.SHP`. Static feature layers use the island-specific `Ixx-FEAT.SHP`. The two original HZT lookup banks are reconstructed and loaded with the island palette; triggered feature states, scene haze application, most game simulation, and dynamic discovery remain unimplemented. The Hall reserve buttons `BC_HallStkB/C/M` use `THBUTT.SHP`, their `windows.txt` panes and hover frame, and the mode cycle from `FUN_0045f755`. Mode 2 now creates/cancels the source's deferred type-4 requests when the Hall's observed active bit and stock threshold allow it; the initial Hall bit is off and its activation path remains unknown. A newly corrected click path dismisses `IWConstruct` when clicking outside its panes so the Hall can be selected and its controls reached; this UI path still needs a runtime check. Other site dots and most of the lower bar remain remake interaction aids rather than reconstructed controls. Clicking an empty constructible pad opens the `IWConstruct` grid using the panes and templates from `windows.txt`; hovering an item updates the matching `IWConstructInfo` pane, and `BuildCycle` changes pages. The grid uses the original ordered candidates and per-tribe item sprites. Selecting a grid item follows `FUN_0043acea` (`0x34` selection then `0x33` close). **Construction fidelity is incomplete:** the current prototype still places an item immediately after site validation (`FUN_00452656`) and initializes its runtime counters and flags (`FUN_004528ca`); this does not reproduce the observed queued worker order (`FUN_0045da80`) and must be replaced by the deferred task cycle before claiming construction gameplay. Resource balances, tone deduction and worker execution are incomplete. The Load screen uses the original `LOADSAV0.SHP` artwork. It scans the eight `%02d.sav` slots read-only and applies the Ghidra-observed 0x80-byte header, `1.16` version prefix, and `0x378b8` marker. Clicking an empty slot returns to the title screen, as the original handler does; valid files get a clear notice because full save restoration is not implemented yet. The installed eight `.SAV` files are all one-byte placeholders, so none are loadable. Resume is not connected to savegame restoration. The 640×480 surface stays 4:3 when resized, and mouse hit testing uses the letterboxed viewport.

The generic descriptor loader is grounded in `FUN_0046cd22` and the `windows.txt` records; it preserves the two extra `PANE` values seen on stockpile controls. The Hall reserve controls now use those panes and the documented `THBUTT` frames, and route to the `FUN_0045f755` cycle. The portable `IWConstruct` model captures the observed four-column hover/click selection, page cycling, selection messages, the `IWConstructInfo` selected-item message, and the `BuildCycle` visibility threshold (`item_count > 4`) from `FUN_0043aa9f`, `FUN_0043ad79`, `FUN_0043acea`, and `FUN_0043b2d1`. It also ports `FUN_0045f121`'s ordered eight-item candidate filter. Ghidra shows that the candidate size is compared with the selected site's `+0x0c`, not a player size limit; `iw_construct_build_list_for_site` now obtains that value from the parsed pad subtype (`pad`/`smpad` 0, `mdpad` 1, `lgpad` 2). `FUN_0043aee8`/`FUN_0043b369` now ground the composed preview layers, ½-scale grid placement, cost indicator, and description loaded via `bldtxt.txt`. The `pad.txt` disabled-cost marker, player-specific item IDs, and executable island-count thresholds are applied. The live rule-set/island-count producers and full economy/queued placement transaction remain open. Tests validate the size source, per-player lookup, filters, `BuildCycle` descriptors, Hall control manifest data, and the pure construction-grid/cycle/outside click-routing decision; they do not exercise Win32 runtime accessibility. The island click router now dismisses `IWConstruct` on outside clicks to allow selecting the Hall and reaching its stock controls; verify this interaction in the application. The directory layout and fixed widths come from static bytes plus the Ghidra COB loader (`FUN_0040ff5b`); C error handling and API shape are remake implementation choices. Island location tag validation follows the explicit string comparisons in `FUN_00461b3b`. Offsets are required to increase strictly because that is true of both supplied archives. Member lookup is exact and case-sensitive. No assumptions are made about game-rule meanings beyond the format labels recorded in `FLOAT_decompilation` documentation.
