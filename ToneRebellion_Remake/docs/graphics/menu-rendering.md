# Menus et rendu de demarrage

## Initial floater drawing on an island

Ghidra identifies `FUN_0042704b` (`fltdraw.cpp`, `0x42704b`) as the painter used to compose a floater from separate body and legs SHP sheets. In the initial-world path, `FUN_0046466f` calls `FUN_00462a87(player, 0, markerX, markerY)` four times per player. Local `fltinf.txt` maps each tribe's worker item to its body and leg shape names; local `shapeinf.txt` maps the base worker to body frame 0 and idle hover legs frames 0–15. `shapes.txt` maps those names to `data\pbod.shp`/`plegs.shp`, `sbod.shp`/`slegs.shp`, `mbod.shp`/`mlegs.shp`, and `lbod.shp`/`llegs.shp`. The remake now loads these eight original sheets from `TONE01.COB` with the selected island palette and draws the initial floater instances on their assigned island, legs first and body over them. The 33 ms UI animation advances the hover frame modulo 16; exact game-tick phase, offsets caused by live movement/collision, and the full state-dependent behavior in `FUN_0042704b` are still unresolved. The underlying rendering observations come from the binary pseudocode; the filenames and frame ranges come from the local original data files.

## Evidence-backed asset path

The remake reads original assets from `C:\Program Files\Tone\TONE01.COB` in read-only mode. The new-game palette is `data\newgame.pal`; the title screen palette is `data\titscrn.pal`. The asset names and their roles are also present in the local `shapes.txt`: `NEWBACK`, `TITSCRN`, `NEWBUTT`, `GLYPHS`, `NGREALMS`, `BIGFLOAT`, and `LEVIDIFF`.

The SHP decoder follows the Ghidra decompilation of `FUN_00404770` at `0x404770` and its unclipped fast path `FUN_00404b74` at `0x404b74`. Observed frame records have an 8-byte frame-directory entry, an offset-relative frame record, signed drawing bounds, and a byte RLE stream. In the RLE stream, a zero token ends a row, an even nonzero token repeats the next palette index, an odd nonzero token copies that many literal palette indices, and token `1` skips a count from the next byte before continuing at the following token. These are observations from Ghidra's pseudocode, not recovered original source.

The game bitmap-font path is reconstructed from `FUN_0046cd22`, which loads `data\\bgoutfnt.fnt`, and the font routines `FUN_004289ec`, `FUN_00408287`, and `FUN_004082a7`. The observed font header contains the `1.` marker, glyph count, glyph height, maximum width, and a 32-bit offset table. Each glyph offset points to a 32-bit width followed by `width × height` mask bytes. In the supplied font the pixel values are `0` (background), `1` (ink), and `0xff` (transparent); Ghidra shows `FUN_004082a7` passing values through a translation table and skipping translated `0xff`. The remake parses this layout into [font_image.c](../../src/data/font_image.c) and renders only value `1` as foreground. An earlier renderer mistakenly painted value `0` as foreground, filling glyph bounding boxes and causing the blocky text. The help paragraphs are read from `tonehelp.txt` in `TONE00.COB`; those assets use the original DOS/OEM byte indices expected by the font table.

The 768-byte palettes contain 256 RGB triples whose observed components are in the VGA range 0–63; the renderer scales these to 8-bit RGB. The SHP transparent-run encoding supplies the alpha mask; palette index zero is not assumed to mean transparent. The decoder bounds each image by the next distinct frame offset because consecutive directory entries can alias one encoded frame. A frame containing only its 24-byte header is a transparent image. The first words in that header are not required to be nonzero; the signed draw bounds beginning at byte 8 define its dimensions.

## New-game footer overlay

**Observation from local data:** `shapes.txt` maps `data\ngmeintr.shp` to `NEWBUTT`. Decoding that sheet from the installed `TONE01.COB` gives frame 0 a 640×73 image at vertical offset 407, with opaque pixels. The configured entries in `windows.txt` describe the individual footer controls and do not describe this full-width frame. This matches the continuous curved footer visible in the supplied original-game capture and the earlier remake capture.

**Remake change:** frame 0 is drawn once through the `NEWGAMWND` descriptor. The hover resolver now ignores descriptors without a caption; previously `-1 == -1` selected frame 1 and drew the back button at the descriptor's `(0,0)` pane. `test_window_catalog` covers that sentinel case; `test_island_cob` checks the footer frame bounds. This does not establish full screen parity.

## Original menu composition used by the remake

- Title art uses frame 0 of `TITSCRN` as the 640×480 background and frames 2, 4, 6, and 8 at the four button panes from `windows.txt`.
- The load screen uses `LOADSAV0.SHP` frames 0 and 1. `windows.txt`'s load-state background and overlay both cover the 640×480 client area. The remake scans the eight save slots with the original header checks and returns to the title when an empty slot is clicked; valid-save restoration remains unimplemented.
- New-game art uses `NEWBACK` frame 0, the full-screen/bottom strip `NEWBUTT` frame 0, then button frames 1, 3, 5, 7, 9, 11, 13, and 15 at the panes in `windows.txt`.
- The selected realm, difficulty illustration, and floater come from `NGREALMS`, `LEVIDIFF`, and `BIGFLOAT`. Their frame choices and placement use calls and constants observed in `FUN_0044ec5d` (`functions/0015_batch_0011.md`), with selected tribe and difficulty state substituting for live game globals.
- `GLYPHS` uses the original sheet and its 20-frame per-tribe grouping. The renderer places its four symbols at `(170,240)`, `(320,90)`, `(470,240)`, and `(320,390)`, matching the x/y address tables at `0x4a24c8` and `0x4a24d8` read by `FUN_0044ec5d`.
- The new-game background renderer draws the three dotted orbital rings found in `FUN_0044ec5d`: 8×10 rectangles around `(320,240)` at radii 150, 170, and 130. Static disassembly shows each base value `-50`, `-30`, or `-70` is offset by 200 before multiplying `sin`/`cos`; the rectangles use palette index 0. The original adds ten randomized palette pixels per quadrant through the selected ring size. Their 15-bit LCG (`state = state * 0x343fd + 0x269ec3`, output `(state >> 16) & 0x7fff`), color range, and per-pixel coordinate jitter now follow `FUN_00474b90` and `FUN_0044ec5d`; its seed still differs because the original seeds from `QueryPerformanceCounter` and consumes the same global RNG elsewhere. The 20-frame glyph cycle and 17-frame floater cycle are driven by a 33 ms Win32 timer. `FUN_0044ec5d` draws two overlapping floater frames (base plus animation); the remake now does the same, while exact global clock phase and bobbing curve remain approximate.
- Clicking Begin or pressing Enter from new-game opens a map view using `MAPBACK` frame 0 and `SMISLE`, with `MAINMAP.PAL`. Island angle/range/height/shape records and explicit bridge pairs come from the local `data\\worldpos.txt` member. `FUN_004718eb` builds display entries for the islands and bridges; `FUN_00471e66` selects one of three 15-frame SMISLE groups: frame base 0 for an inhabited island, 15 for an uninhabited island, and 30 for the selected homeworld. The remake initializes WORLDPOS entries 0–3 as the four homeworlds, marks the chosen tribe's homeworld with base 30, the other homeworlds with base 0, and remaining islands with base 15. This matches the shipped data layout and handler branch; dynamic ownership after starting a game is not implemented.
- `FUN_00471536` computes map positions as `x = centerX + trunc(cos(angle - phase) * range * 0.129999995 + 0.5)` and `y = centerY - trunc(sin(angle - phase) * range * 0.060000002 + z * 0.060000002 + 0.5)`. `FUN_004701ef` initializes the two scale fields and phase offset. Ghidra's recovered helper bodies at `0x477ab4` and `0x477314` stop after their calls to the floating-point loader; static disassembly of their following bytes shows `FCOS` at `0x477ad2` and `FSIN` at `0x477332`, confirming the trig operations. The code adds `0.5` then calls `__ftol`, which truncates toward zero; the remake follows both operations. It uses initial phase zero and the map center `(320,240)` from the 640×480 world pane.
- `FUN_00471b74`, called for each active bridge display item, clips bridges unless both endpoints lie inside the map pane and then writes 10 pseudo-random pixels per segment. It initializes an eight-color ramp from the current palette by nearest-color matching the RGB values `(5+7i, 5+2i, 45+2i)`, `i=0..7`; `FUN_0041081b` supplies that nearest-color search. `FUN_004718eb` adds a bridge display item only when the bridge record's first dword at `DAT_006136b4 + index*8` is nonzero; the island endpoint indices occupy the following words. The bytes in Ghidra's loaded image for the bridge table and its count are zero; this establishes the static image contents only, not the values after runtime initialization. `FUN_004702d9` has an input handler (`param_1 == 5`, `param_2 == 0x4f`) that sets every counted bridge flag to 1 when parameter bit `0x100` is absent, otherwise 0; `FUN_00464e4d` later clears active flags probabilistically during its state-3 transition. Thus the binary distinguishes static WORLDPOS possibilities from currently active/rendered links, but the exact initialization point and values at map entry remain unresolved. In the remake, a link is now drawn only when its per-link runtime flag is active **and** both island sessions contain reciprocal class-2 bridge markers paired to that WORLDPOS edge by the `FUN_00461859` rule. This prevents rendering a bare WORLDPOS possibility as a built connection. The original event that activates/deactivates flags remains unconnected to building completion; the remake does not guess that relationship. The 33 ms map timer advances continuously without user input. `FUN_00471536` uses `DAT_00618e44 % 0x5a0`, then divides the angular phase by four, giving 0.25 degrees per counter increment; the original counter's exact timer cadence is not established. The remake uses that angular step per 33 ms timer tick and refreshes bridge-particle positions. Hit testing uses the same animated island positions and the normal frame's opaque bounds, so switching to a hover sprite does not move the cursor target; the hit-test also runs on each map timer tick so a stationary pointer tracks the moving islands. `FUN_00471e66` selects the inaccessible `+15`, reachable `+0`, and reachable-and-selected `+30` SMISLE groups; the remake applies `+30` only while the pointer is over an accessible island, and inaccessible islands keep `+15`. The exact line interpolation and global render ordering are approximations because Ghidra's x87 helper boundaries cut off the full floating-point expressions.
- Bridge rendering now also requires the original per-object completion marker: `FUN_004669bd` sets bit 0 of each paired bridge object's dword at `+0x1c` while activating the corresponding WORLDPOS flag. The remake tracks that as `GameRuntimeLocation.bridge_constructed`; possible bridge sites or a globally enabled link alone do not render a connection. The current building UI still does not produce the original bridge-completion event, so this correctly keeps unbuilt links hidden until that gameplay path is ported. Bridge sparks are now derived from the map animation tick and edge/segment indices; repeated `WM_PAINT` calls no longer advance the gameplay RNG. The existing 33 ms world-map timer rotates the islands and repaints the scene without input, while hit-testing the moving island frames for reachable-island hover highlighting.
- `FUN_00472013` hit-tests map islands in reverse display order against opaque SHP bounds computed by `FUN_00405e11`. The remake retains those bounds, reads island labels from `names.txt`, and shows the label on hover or selection. Enter or a second click opens the selected island screen; Enter with no selection opens the chosen tribe's homeworld. The latter is a remake navigation choice based on `WORLDPOS` entries 0–3 being the homeworlds.
- The island-window initialization path in `FUN_004337d9` (`islewin.cpp`) resolves the active map item, sets a 2560×320 world extent, and loads `data\island%02d.pal`, `data\island%02d.hzt`, `data\%s%02d.SHP`, and the island-specific `data\i%02d-feat.shp`. The default `island` SHP from the local COB has one 2560×320 frame. The remake loads that panorama and palette, crops a 640×320 viewport, and scrolls horizontally over the original image. `FUN_00461b3b` (`tworld.cpp`) reads `data\ISLAND%02d.TXT` into an ordered location table; the C parser preserves IDs, coordinates, raw type labels, and special values, validates at most 100 entries and the observed 0–2559 by 0–319 extent, and maps the eleven accepted tags (`tone`, `pad`, `smpad`, `mdpad`, `lgpad`, `special`, `bridge`, `levhub`, `levshld`, `feature`, `feattrig`) to explicit kinds and original renderer class/subtype/variant fields. The original parser rejects unrecognized tags. `FUN_00461b3b` assigns `tone` to renderer class 1 (the start-marker class) and `pad` plus the size-specific pads to class 0; subtype/variant and raw tag remain distinct, so dispatch `tone` to its pool animation before generic pad rendering. Local `shapes.txt` maps `POOL` to `data\tone.shp` and `PADS` to `data\pad.shp`; `bldinf.txt` defines `POOL` frames 2–40 with a three-tick ping-pong (`CHUG 2 40 3 P`) and `PADS` with its separate loop. The remake renders `tone` using the 40-frame `TONE.SHP` pool animation; Ghidra shows the POOL special case in generic `FUN_0040bf98`. `FUN_0040ab42` is the separate `PADS` site animation. Its 27-frame `PAD.SHP` asset forms three nine-frame size groups for `smpad`, `mdpad`, and `lgpad` only. `levshld` also has class 0/subtype 0 in the raw parser, but `pad.txt` and `bldinf.txt` map the Leviathan shield item variants to base frames 1–14 of `SPEARS.SHP`; because `ISLANDnn.TXT` does not identify a variant for each row, the remake leaves these as inspection markers instead of guessing a shield frame. This classification follows the shipped asset metadata and original renderer evidence; the animation tick cadence remains approximated by the remake's 33 ms timer. The 33 ms window timer is an approximation of the original game tick cadence; tribe visibility flags are not represented in `ISLANDnn.TXT`. The remake also loads the matching `i%02d-feat.shp` for each island and transcribes the non-triggered branch of `FUN_0040b345`, including its per-island frame selection and world coordinates driven by the location's `special_value`. `FUN_00432940` is the original location draw-order comparator and sorts by ascending world Y; the remake uses that order for pad and feature layering. Frame counts in the local corpus match the renderer's referenced indices for all 15 islands. Triggered/active feature layers and HZT treatment depend on live object flags and altitude and remain unimplemented. Exact runtime palette/HZT treatment is not reconstructed. A drawable runtime item now replaces `PAD.SHP` at its occupied site; an unoccupied typed pad keeps its animated construction ring. The `pad.txt` catalog entries with item IDs 1 (`PIT_Object`) and 3 (`PIT_FeatureTrigger`) are omitted because their shape is `noshape`; those catalog item IDs are distinct from the island renderer-class field. class-3 `special` locations still use colored inspection markers, and the status footer and click-to-inspect interaction are remake scaffolding.
- The original initialization also passes the 3584-byte HZT member through `FUN_00410510` to build palette lookup tables. The remake now recreates both 8×256 lookup tables in `src/core/island_haze.c`: the HZT supplies seven 256-byte levels per bank, `FUN_004106dd` selects the second bank when its selector is zero, and `FUN_00410510` generates level 7 by nearest-color matching to RGB6 black or white while preserving index 255. The tables are loaded with each island palette. Their application to sprites is still pending because the scene-specific haze levels have not yet been reconstructed. Original non-pad site sprites, terrain effects, units, and simulation are also pending. Runtime captures from the remake show the actual island panorama and a selected site at `ToneRebellion_Remake/build/island_view/island-view.png` and `ToneRebellion_Remake/build/island_view/island-location-selected.png`; they are not captures of the original game.
- `Esc` returns from the map view to new-game setup; Left/Right changes the selected world size before or after entering the view.

## Scope and remaining fidelity work

The title, setup, world map, and first island panorama now use original art from the shipped COB. Remaining gaps include exact animation phase, music, bridge effect timing, the selected homeworld frame variant, application of the reconstructed HZT tables, remaining surface-site sprites, and the simulation/game screens. The title-screen SHP button frames already contain their blue captions, so the remake no longer draws a second yellow caption over them. The `RESUME` pane and help mapping follow `windows.txt` and `tonehelp.txt`; the original's availability check reads a 0x80-byte `resume.gam` header and compares its last dword with `0x378b8` (`FUN_004489c0` and `FUN_00457490`). This remake mirrors that check, but does not yet load a valid save. The local `resume.gam` is one byte, so Resume remains inactive here. The Load screen recognizes the original eight `%02d.sav` slots using the `FUN_00458371` 0x80-byte/version/marker checks, and `FUN_00458162` supplies the two-column, four-row slot addressing and empty-slot close behavior. All eight installed `.SAV` files are one-byte placeholders. Valid save restoration remains unsupported. New Game uses its contextual `gamey.txt` captions as described below. The original binary was not executed during this work.

The 640×480 game surface is letterboxed to preserve its 4:3 aspect ratio in the resizable remake window. Mouse coordinates are transformed through that same logical viewport, so hit testing remains aligned when the window is resized or letterboxed.

Earlier remake captures exercised New Game tribe selection, captions, difficulty, world size, Begin, and Escape. They predate the current text sampler and are not visual validation of this build. No original executable was run.

The load/save menu now scans all eight `%02d.sav` files in read-only mode. Its validator follows `FUN_00458371` (`0x458371`): it reads a 0x80-byte header and checks the `1.16` prefix and `0x378b8` marker. The local `00.SAV`–`07.SAV` files are each one byte and fail this test. `FUN_00458162` (`0x458162`) maps the two columns and four rows to those slots; clicking an empty slot closes the load screen. The current remake was exercised by opening Load and clicking an empty slot, which returned to the title screen (`load-screen-current.png`, `load-empty-return.png`). If a valid header is supplied, the remake explains that full state restoration is still unsupported rather than pretending to load it.

## New-game menu paint and feedback follow-up

Static Ghidra evidence for `FUN_0044ec5d` confirms that the New Game painter registers the eight named controls `EXITNEWGAME`, `WORLDSIZE`, `TRIBE0`–`TRIBE3`, `DIFFICULTY`, and `BEGINGAME`. The local `windows.txt` maps these IDs to button panes, and `tonehelp.txt` supplies their French explanations plus the full-screen `NEWGAMWND` help. The title menu displays original help text only when a control is hovered and switches to the alternate SHP frame for the hovered button. On New Game, the painter selects one of eight short localized strings (`NEWGAME0`–`NEWGAME7`) for the hovered control or central tribe symbol, then calls the text renderer at logical y=430 (`0x1ae`). These strings are present in local `gamey.txt` inside `TONE00.COB`; the remake now loads them and renders the selected caption centered in the lower strip with `BGOUTFNT.FNT`. This replaces the earlier, oversized full-help overlay on New Game. The painter also shows the selected tribe's floater as a base frame plus a cycling frame in `BIGFLOAT`. The original 68-frame sheet has four 17-frame tribe groups; each group's first frame has different offsets from its 16 animation frames, which the draw path preserves.

The reported black flash had a direct cause in the remake: `WM_PAINT` cleared the complete visible client area to black immediately before blitting the already-complete off-screen frame. The paint path now leaves the game viewport intact and clears only letterbox bars. The existing `WM_ERASEBKGND` handler continues to suppress background erasure.
