## Correction: métriques de largeur du texte courbe (REA relu: `FUN_00428baa`, `ev_4fa53e73`)

`FUN_00428baa` uses the same width function (`FUN_0042892d`) to break the lines (longest group of words that fits, stepping back one space at a time), for the natural line width and for each word's advance: extra gap = `(box_width - line_width) / space_count` (at least 1 space), the remainder adding 1 pixel to the first gaps; each word advances by `word_width + width(" ") + gap`. The last line is justified like the others.
The port drew the glyphs at 11/13 of their width but broke and spaced the words with the source widths (13/13), hence very large gaps between words. `measure_curved_bitmap_text` (`bitmap_text_layout.inc`) now uses the reduced widths (same rounding as the drawing, at least 1 pixel) for the line break, the natural width and the word advance. Not checked visually: the layout changes (more words per line, fewer lines); the calibrated bottom anchor (`CURVED_TEXT_NEWGAME_LAST_LINE_Y`) is unchanged.
