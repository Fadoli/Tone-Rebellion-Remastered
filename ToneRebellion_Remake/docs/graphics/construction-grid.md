# Construction grid and task detail

### Construction grid on the island view

The island screen opens the construction grid when an empty class-0 pad is clicked. Its geometry and candidate drawing follow `windows.txt`, `FUN_0043aa9f`, `FUN_0043aee8`, and the preview helpers. The grid click follows `FUN_0043acea` by sending item message `0x34` and close message `0x33`; `FUN_0042fa0f` turns that selection into a 16-byte category-0/type-5 request containing the selected site and item. The remake now queues that packet without immediately placing an item. The outbox cap of 64 is a remake storage limit. The packet consumer remains unidentified, and its link to `FA_Build` travel and arrival validation is unresolved. `FUN_0045da80` assigns `FA_Cast` (`0x13`), a separate action whose target resolver does not move current coordinates. See [construction evidence](../../../behavior/island-construction.md) and [floater movement evidence](../../MOVEMENT_REVERSE_ENGINEERING.md).

Task controls use their `MOUSEFOCUS` hover frames; list scrolling is bounded. The remake shows source-backed task rows, selected-row palette remapping, priorities, and `CONSTR`/`STOCK`/`REPAIR` gauges. These gauge targets use payload `+0x0a` as island and `+0x0e` as location. Reserve details show `DELIVER`, the resource category, and centered frame-4 art. Construction details show `BLDCONST`, the player's BLDNAME entry, and the half-scale static preview drawn by `FUN_004469d6`. Construction/damage simulation remains absent; evidence and limits are in `[FUNCTION_GUIDE.md](../../../FUNCTION_GUIDE.md)`.

**Remake refresh policy:** the complete screen is repainted at each 33 ms simulation tick (about 30 Hz), including while Tasks is selected. Original `FUN_004459e6` renders visible rows, but static analysis does not establish its invocation cadence. See [cadence benchmark](../../bench/task-render-cadence.md).

The Inventory info pane now reads the last selected item ID, which the source sends to `IWTextInfo` in detail mode 2 (`FUN_0043d45c`/`FUN_0043d41a`); clearing the pointer hover no longer clears the detail text. This selection/hover distinction is covered by `test_island_panel_info`. The source input event mapping is still unresolved, so the existing hover-to-select gesture remains a remake assumption.
