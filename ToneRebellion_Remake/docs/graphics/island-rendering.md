# Interface et rendu insulaire

## `IWLocInfo` roster

The remake now draws and allows clicks on the four initial workers at the selected player's starting Hall. Source-derived slot geometry, the `0x2f` alternate layout, and strict hit bounds are covered by `island_panel_info` tests. Later units and some `FUN_0042704b` effects are not modeled; this pane has no runtime comparison. Function evidence and exact anchors are in `[FUNCTION_GUIDE.md](../../../FUNCTION_GUIDE.md)`.

## Island viewport and original interface template

The local `windows.txt` descriptor gives `ISLEVIEW` the pane `(0,0)`–`(639,319)` and `ISLETMP` the pane `(0,320)`–`(639,479)`. `FUN_0044964f` loads `data\\ISLETMP%d.SHP` using its player argument, or the active player index when passed `-1`; Ghidra's pseudocode therefore establishes that the lower template artwork is player-specific. The remake now selects `isletmp%d.shp` from the active session tribe instead of always loading variant 0, while decoding it with the selected island's palette. All four variants are present in `TONE01.COB`, and a corpus check requires each to contain a decodable 640×160 frame. `shapes.txt` lists `ISLETEMP` as `isletmp0.shp`, but that static manifest entry does not supersede the dynamic per-player loader observed in Ghidra. The remake draws this frame at `(0,320)`, clips location sprites to `ISLEVIEW`, and applies the same 320-pixel boundary to location hit testing. `windows.txt` also places `IWLilMap` at `(192,328)` with a 256×32 pane, and `shapes.txt` maps it to the 16-frame `LILMAP.SHP` (`TONE01.COB`). The remake draws a frame corresponding to the selected island surface ID in that pane; this frame-to-island mapping remains an inference because Ghidra class evidence confirms the `IWLilMap` window exists but does not yet establish its frame-selection rule. Remake-only island, scroll, selected-location, and runtime-state diagnostics were removed from the bottom panel because they obscured original template artwork and selected-object information. The actual interactive island-window hierarchy is still not instantiated, so some lower panes remain incomplete.


The island renderer now draws class-2 bridge locations using frame 0 of BR-TRG01.SHP. Static evidence: FUN_00461b3b maps the `bridge` tag to renderer class 2, the shipped `bldinf.txt` declares BR-TRG01 with BASE 1 1, and the COB sheet contains 23 frames. Choosing this base sprite for the map location remains an inference pending comparison with the original game's rendering.

### Runtime building items and their animation segments

The remake now reads `pad.txt` and `bldinf.txt` from `TONE00.COB`. `pad.txt` row IDs identify runtime item records; the `ITEM`/optional `SHAPE` and animation records in `bldinf.txt` provide the sprite sheet and segments. Ghidra identifies `FUN_0040bf98` as the generic item renderer. On island load the remake resolves runtime IDs actually present there, loads their SHP sheets from `TONE01.COB`, and draws each item over its location, including the player-specific halls (`0x2a + 16 × player`) and initial tone marker IDs 6–9. It now parses and draws `BASE`, `CHUG`, `GLYP`, `INCI`, `CONS`, `PROD`, and conditional `OCCU` layers. The animated `PROD` frame is drawn at the item anchor. Its descriptor offsets are used only by a conditional threshold overlay, not by that frame. The unoccupied `POOL` and `PADS` paths remain separate because those `bldinf` records are named entities, not `pad.txt` item IDs.

`FUN_0040bf98` selects `BASE` from the item step at `+0x4a` (clamped to the declared range, with flag `0x20` adjusting the step), then draws `CHUG` from `+0x3a / speed` and `GLYP` by mapping `FUN_0040ab05(0, 20, +0x3c)` across its endpoints with `FUN_0040aab0`. It also selects `INCI` from `+0x3e`, `CONS` from `+0x40` and flag `0x004`, and `PROD` from `+0x42` and flag `0x002`. The animated `PROD` frame is drawn at the item's x/y anchor; only the conditional threshold overlay uses the descriptor's x/y offsets. The remake previously applied those offsets to the animated frame too; that is corrected and covered by position tests. `OCCU` is drawn only when flag `0x008` is set. The remake mirrors these frame/layer decisions, but initializes the additional counters to zero until their game events are ported. The function's x86 instructions show `BARG` computes `(last-first+2) * *(double *)(object+0x50)`, converts with `FISTP` (round-to-nearest, ties-to-even), offsets from the first frame, and clamps to the last. The remake ports this formula, but the gameplay meaning/update of `+0x50` remains unknown and its initial session value is zero. `PROD` projectiles/secondary effects remain pending. For construction sites only, `FUN_0040ab42` resolves the `PADS` segment and computes `global_ticks / (speed + object[+0x0c]) + world_x % 23`, then wraps over the nine declared frames. `FUN_00461b3b` stores the size subtype at that runtime offset (`0` small, `1` medium, `2` large); the remake now passes that observed subtype into the `PADS` phase calculation. A site circle disappears as soon as an item ID occupies that record, whether or not its SHP is available. Regression coverage is in `tests/test_building_render.c` and `tests/test_island_render_rules.c`, including checks against the local original `pad.txt` and `bldinf.txt` corpus.

The tone-pool renderer follows `FUN_0040bf98`'s layered draw order for `POOL`: static `BASE 1 1`, then animated `CHUG 2 40 3 P` from `bldinf.txt`. In zero-based SHP indexing, the remake draws frame 0 before the animated overlay. `FUN_00450a71` gives runtime IDs 0 and 5 separate counter tracks: ID 0 traverses counters 0..89 then restarts, while ID 5 traverses 0..125 then repeats 102..125. `FUN_0040bf98` divides each counter by speed 3 and selects a ping-pong frame using `FUN_0040ab05`. This is two runtime counter tracks on one POOL SHP/CHUG segment, in addition to the BASE-plus-CHUG compositing. For ID 0, `FUN_0040bf98` freezes the displayed counter at zero while the pool is unowned, the active tribe's visibility bit is absent from object byte `+0x22`, and the counter is below 90. `FUN_0046466f` sets each player's bit on that player's selected tone marker. The remake now models this byte and applies the same display gate; it seeds player-start markers from `FUN_0046466f`, while later discovery updates remain unimplemented. Tests cover the two tracks, their wrap points, the visibility gate, and player marker bits. The animation does not use the `world_x % 23` phase that `FUN_0040ab42` applies only to `PADS`. The 33 ms Win32 timer still approximates original game tick cadence. POOL art is hidden when the runtime item is a Leviathan building, leaving the building unobscured.

The generic painter is called by `FUN_0040b09a` and `FUN_0040b2e6` with the item's world point translated by the island-window origin and horizontal scroll, and with game-render mode enabled (`1, 0x10000, -1`). `FUN_0040bf98` also draws conditional item-specific visuals after the data-driven layers: threshold overlays at `PROD` offsets and special production effects for selected item IDs. Those extras are not yet ported, so this is a partial recreation of the original painter, not a claim of complete building visuals. `FUN_00450a71` is the per-object game tick: it advances `+0x3a`, `+0x3c`, `+0x3e`, `+0x40`, and `+0x42` under object-class and flag conditions, and clears some activity flags when an animation finishes. The remake now advances active `CONS` and `PROD` counters and clears flags `0x004`/`0x002` at the thresholds recovered through `FUN_00456b8d` and `FUN_00456bd0`; item-specific completion side effects, construction/production event producers, INCI-trigger allocation, and special effects remain incomplete.

### Construction grid on the island view

The island screen now opens the construction grid when an empty class-0 pad is clicked. Its pane rectangle, backdrop frame, and cycle-button pane come from the `IWConstruct`, `IWConstructInfo`, and `BuildCycle` entries in the local `windows.txt`; the four-column hit geometry, hover message `0x3c`, info message `0x9a4`, and page event `0x45` follow `FUN_0043aa9f`, `FUN_0043ad79`, and `FUN_0043b2d1`. `FUN_0043aee8` positions each candidate at `pane_width/8 + column*pane_width/4`, draws its full temporary-object preview through `FUN_0040d3e1`/`FUN_0040bf98` at half scale, then draws the cost indicator from `bildtone.shp`. The info pane uses the full-scale layered preview, matching cost frame, and `pad.txt` text ID resolved through `bldtxt.txt`, as observed in `FUN_0043b369`. The preview renderer composites the layers declared in `bldinf.txt`; its zeroed activity counters model a static idle preview, not a running construction animation. Initial owned-island count is one, from the four starting halls. The rule-set source remains unknown; the current initial candidate list uses rule-set index 0, but only candidate 44's threshold passes at owned count one and that threshold is the same in all three observed tables. The grid click follows `FUN_0043acea` by selecting the item through message `0x34` and closing with `0x33`. The remake's following site click applies the size and disabled-cost validation observed in `FUN_00452656`, stores the player-block item ID and owner, and initializes runtime flags/counters as in `FUN_004528ca`. Tone affordability, balance deduction, and the full queued/network transaction remain unresolved; placement is still a simplified gameplay path. The separate POOL/basin renderer and its animation are unchanged by this construction-window work.

Task controls use their `MOUSEFOCUS` hover frames; list scrolling is bounded. The remake shows source-backed task rows, selected-row palette remapping, priorities, and `CONSTR`/`STOCK`/`REPAIR` gauges. These gauge targets use payload `+0x0a` as island and `+0x0e` as location. Reserve details show `DELIVER`, the resource category, and centered frame-4 art. Construction details show `BLDCONST`, the player's BLDNAME entry, and the half-scale static preview drawn by `FUN_004469d6`. Construction/damage simulation remains absent; evidence and limits are in `[FUNCTION_GUIDE.md](../../../FUNCTION_GUIDE.md)`.

The Inventory info pane now reads the last selected item ID, which the source sends to `IWTextInfo` in detail mode 2 (`FUN_0043d45c`/`FUN_0043d41a`); clearing the pointer hover no longer clears the detail text. This selection/hover distinction is covered by `test_island_panel_info`. The source input event mapping is still unresolved, so the existing hover-to-select gesture remains a remake assumption.
