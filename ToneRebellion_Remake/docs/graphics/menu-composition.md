# Original menu composition

## Original menu composition used by the remake

- Title art uses frame 0 of `TITSCRN` as the 640×480 background and frames 2, 4, 6, and 8 at the four button panes from `windows.txt`.
- The load screen uses `LOADSAV0.SHP` frames 0 and 1. `windows.txt`'s load-state background and overlay both cover the 640×480 client area. The remake scans the eight save slots with the original header checks and returns to the title when an empty slot is clicked; valid-save restoration remains unimplemented.
- New-game art uses `NEWBACK` frame 0, the full-screen/bottom strip `NEWBUTT` frame 0, then button frames 1, 3, 5, 7, 9, 11, 13, and 15 at the panes in `windows.txt`.
- The selected realm, difficulty illustration, and floater come from `NGREALMS`, `LEVIDIFF`, and `BIGFLOAT`. Their frame choices and placement use calls and constants observed in `FUN_0044ec5d` (`functions/0015_batch_0011.md`), with selected tribe and difficulty state substituting for live game globals.
- `GLYPHS` uses the original sheet and its 20-frame per-tribe grouping. The renderer places its four symbols at `(170,240)`, `(320,90)`, `(470,240)`, and `(320,390)`, matching the x/y address tables at `0x4a24c8` and `0x4a24d8` read by `FUN_0044ec5d`.
- The new-game background renderer draws the three dotted orbital rings found in `FUN_0044ec5d`: 8×10 rectangles around `(320,240)` at radii 150, 170, and 130. Static disassembly shows each base value `-50`, `-30`, or `-70` is offset by 200 before multiplying `sin`/`cos`; the rectangles use palette index 0. The original adds ten randomized palette pixels per quadrant through the selected ring size. Their 15-bit LCG (`state = state * 0x343fd + 0x269ec3`, output `(state >> 16) & 0x7fff`), color range, and per-pixel coordinate jitter now follow `FUN_00474b90` and `FUN_0044ec5d`; its seed still differs because the original seeds from `QueryPerformanceCounter` and consumes the same global RNG elsewhere. The 20-frame glyph cycle and 17-frame floater cycle are driven by a 33 ms Win32 timer. `FUN_0044ec5d` draws two overlapping floater frames (base plus animation); the remake now does the same, while exact global clock phase and bobbing curve remain approximate.
- Clicking Begin or pressing Enter from new-game opens a map view using `MAPBACK` frame 0 and `SMISLE`, with `MAINMAP.PAL`. Island angle/range/height/shape records and explicit bridge pairs come from the local `data\\worldpos.txt` member. `FUN_004718eb` builds display entries for the islands and bridges; `FUN_00471e66` selects one of three 15-frame SMISLE groups: frame base 0 for an inhabited island, 15 for an uninhabited island, and 30 for the selected homeworld. The remake initializes WORLDPOS entries 0–3 as the four homeworlds, marks the chosen tribe's homeworld with base 30, the other homeworlds with base 0, and remaining islands with base 15. This matches the shipped data layout and handler branch; dynamic ownership after starting a game is not implemented.
- `FUN_00471536` computes map positions as `x = centerX + trunc(cos(angle - phase) * range * 0.129999995 + 0.5)` and `y = centerY - trunc(sin(angle - phase) * range * 0.060000002 + z * 0.060000002 + 0.5)`. `FUN_004701ef` initializes the two scale fields and phase offset. Ghidra's recovered helper bodies at `0x477ab4` and `0x477314` stop after their calls to the floating-point loader; static disassembly of their following bytes shows `FCOS` at `0x477ad2` and `FSIN` at `0x477332`, confirming the trig operations. The code adds `0.5` then calls `__ftol`, which truncates toward zero; the remake follows both operations. It uses initial phase zero and the map center `(320,240)` from the 640×480 world pane.
- `FUN_00471b74`, called for each active bridge display item, clips bridges unless both endpoints lie inside the map pane and then writes 10 pseudo-random pixels per segment. It initializes an eight-color ramp from the current palette by nearest-color matching the RGB values `(5+7i, 5+2i, 45+2i)`, `i=0..7`; `FUN_0041081b` supplies that nearest-color search. `FUN_004718eb` adds a bridge display item only when the bridge record's first dword at `DAT_006136b4 + index*8` is nonzero; the island endpoint indices occupy the following words. The bytes in Ghidra's loaded image for the bridge table and its count are zero; this establishes the static image contents only, not the values after runtime initialization. `FUN_004702d9` has an input handler (`param_1 == 5`, `param_2 == 0x4f`) that sets every counted bridge flag to 1 when parameter bit `0x100` is absent, otherwise 0; `FUN_00464e4d` later clears active flags probabilistically during its state-3 transition. Thus the binary distinguishes static WORLDPOS possibilities from currently active/rendered links, but the exact initialization point and values at map entry remain unresolved. In the remake, a link is now drawn only when its per-link runtime flag is active **and** both island sessions contain reciprocal class-2 bridge markers paired to that WORLDPOS edge by the `FUN_00461859` rule. This prevents rendering a bare WORLDPOS possibility as a built connection. The original event that activates/deactivates flags remains unconnected to building completion; the remake does not guess that relationship. The 33 ms map timer advances continuously without user input. `FUN_00471536` uses `DAT_00618e44 % 0x5a0`, then divides the angular phase by four, giving 0.25 degrees per counter increment; the original counter's exact timer cadence is not established. The remake uses that angular step per 33 ms timer tick and refreshes bridge-particle positions. Hit testing uses the same animated island positions and the normal frame's opaque bounds, so switching to a hover sprite does not move the cursor target; the hit-test also runs on each map timer tick so a stationary pointer tracks the moving islands. `FUN_00471e66` selects the inaccessible `+15`, reachable `+0`, and reachable-and-selected `+30` SMISLE groups; the remake applies `+30` only while the pointer is over an accessible island, and inaccessible islands keep `+15`. The exact line interpolation and global render ordering are approximations because Ghidra's x87 helper boundaries cut off the full floating-point expressions.
- Bridge rendering now also requires the original per-object completion marker: `FUN_004669bd` sets bit 0 of each paired bridge object's dword at `+0x1c` while activating the corresponding WORLDPOS flag. The remake tracks that as `GameRuntimeLocation.bridge_constructed`; possible bridge sites or a globally enabled link alone do not render a connection. The current building UI still does not produce the original bridge-completion event, so this correctly keeps unbuilt links hidden until that gameplay path is ported. Bridge sparks are now derived from the map animation tick and edge/segment indices; repeated `WM_PAINT` calls no longer advance the gameplay RNG. The existing 33 ms world-map timer rotates the islands and repaints the scene without input, while hit-testing the moving island frames for reachable-island hover highlighting.
- `FUN_00472013` hit-tests map islands in reverse display order against opaque SHP bounds computed by `FUN_00405e11`. The remake retains those bounds, reads island labels from `names.txt`, and shows the label on hover or selection. Enter or a second click opens the selected island screen; Enter with no selection opens the chosen tribe's homeworld. The latter is a remake navigation choice based on `WORLDPOS` entries 0–3 being the homeworlds.
- The island-window initialization path in `FUN_004337d9` (`islewin.cpp`) resolves the active map item, sets a 2560×320 world extent, and loads `data\island%02d.pal`, `data\island%02d.hzt`, `data\%s%02d.SHP`, and the island-specific `data\i%02d-feat.shp`. The default `island` SHP from the local COB has one 2560×320 frame. The remake loads that panorama and palette, crops a 640×320 viewport, and scrolls horizontally over the original image. `FUN_00461b3b` (`tworld.cpp`) reads `data\ISLAND%02d.TXT` into an ordered location table; the C parser preserves IDs, coordinates, raw type labels, and special values, validates at most 100 entries and the observed 0–2559 by 0–319 extent, and maps the eleven accepted tags (`tone`, `pad`, `smpad`, `mdpad`, `lgpad`, `special`, `bridge`, `levhub`, `levshld`, `feature`, `feattrig`) to explicit kinds and original renderer class/subtype/variant fields. The original parser rejects unrecognized tags. `FUN_00461b3b` assigns `tone` to renderer class 1 (the start-marker class) and `pad` plus the size-specific pads to class 0; subtype/variant and raw tag remain distinct, so dispatch `tone` to its pool animation before generic pad rendering. Local `shapes.txt` maps `POOL` to `data\tone.shp` and `PADS` to `data\pad.shp`; `bldinf.txt` defines `POOL` frames 2–40 with a three-tick ping-pong (`CHUG 2 40 3 P`) and `PADS` with its separate loop. The remake renders `tone` using the 40-frame `TONE.SHP` pool animation; Ghidra shows the POOL special case in generic `FUN_0040bf98`. `FUN_0040ab42` is the separate `PADS` site animation. Its 27-frame `PAD.SHP` asset forms three nine-frame size groups for `smpad`, `mdpad`, and `lgpad` only. `levshld` also has class 0/subtype 0 in the raw parser, but `pad.txt` and `bldinf.txt` map the Leviathan shield item variants to base frames 1–14 of `SPEARS.SHP`; because `ISLANDnn.TXT` does not identify a variant for each row, the remake leaves these as inspection markers instead of guessing a shield frame. This classification follows the shipped asset metadata and original renderer evidence; the animation tick cadence remains approximated by the remake's 33 ms timer. The 33 ms window timer is an approximation of the original game tick cadence; tribe visibility flags are not represented in `ISLANDnn.TXT`. The remake also loads the matching `i%02d-feat.shp` for each island and transcribes the non-triggered branch of `FUN_0040b345`, including its per-island frame selection and world coordinates driven by the location's `special_value`. `FUN_00432940` is the original location draw-order comparator and sorts by ascending world Y; the remake uses that order for pad and feature layering. Frame counts in the local corpus match the renderer's referenced indices for all 15 islands. Triggered/active feature layers and HZT treatment depend on live object flags and altitude and remain unimplemented. Exact runtime palette/HZT treatment is not reconstructed. A drawable runtime item now replaces `PAD.SHP` at its occupied site; an unoccupied typed pad keeps its animated construction ring. The `PIT_Object` catalog row (runtime item ID 1) has no base building SHP, but its generated collectible overlay uses `+0x24` to select a frame from `alltrigs.shp`. `PIT_FeatureTrigger` (item ID 3) remains omitted because its row is `noshape`; these item IDs are distinct from the island renderer-class field. class-3 `special` locations still use colored inspection markers, and the status footer and click-to-inspect interaction are remake scaffolding.
- The original initialization also passes the 3584-byte HZT member through `FUN_00410510` to build palette lookup tables. The remake now recreates both 8×256 lookup tables in `src/core/island_haze.c`: the HZT supplies seven 256-byte levels per bank, `FUN_004106dd` selects the second bank when its selector is zero, and `FUN_00410510` generates level 7 by nearest-color matching to RGB6 black or white while preserving index 255. The tables are loaded with each island palette. Their application to sprites is still pending because the scene-specific haze levels have not yet been reconstructed. Original non-pad site sprites, terrain effects, units, and simulation are also pending. Runtime captures from the remake show the actual island panorama and a selected site at `ToneRebellion_Remake/build/island_view/island-view.png` and `ToneRebellion_Remake/build/island_view/island-location-selected.png`; they are not captures of the original game.
- `Esc` returns from the map view to new-game setup; Left/Right changes the selected world size before or after entering the view.
