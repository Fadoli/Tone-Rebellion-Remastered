# Runtime building-item rendering

The generic renderer was identified in Ghidra as `FUN_0040bf98`: the remake resolves runtime item IDs through `pad.txt`/`bldinf.txt`, loads each item's SHP, and renders `BASE`, `CHUG`, `GLYP`, `INCI`, `CONS`, `PROD`, conditional `OCCU`, and `BARG` layers. `FUN_00450a71` advances the per-object `+0x3a` CHUG counter only when source flag `0x001` is set for class 0, and advances `+0x3c` GLYP progress while active; `FUN_004528ca` initializes created pads with flags `0x410`, counters zeroed by `FUN_004500c4`, and rate modifier `+0x32 = 1`. These counters and flags are stored per runtime site and advanced by the remake's simulation tick. The tick also advances CONS (`+0x40`, flag `0x004`) and PROD (`+0x42`, flag `0x002`) to their descriptor thresholds. For class-2 item 2, CONS completion starts PROD, and PROD completion activates the paired bridge markers and WORLDPOS edge (`FUN_004669bd`); the CONS-start event remains unmodeled; inspected creation/dispatch paths do not set it (REA `ev_d826b753f8191038400836ecea34b85ff02e6bbb5bca910fd453321238bf4f91`, `ev_172a608b3e973e5da3943a31a5e23bd1bda5867c1da669038f74a156ca719da1`). Other item-specific completion events, PROD projectiles/secondary effects, and the construction transition that sets flag `0x001` remain pending. Ghidra assembly shows `BARG` frame selection uses `(last-first+2) * *(double *)(object+0x50)`, rounds with `FISTP`, offsets from the first frame, then clamps; the remake ports that mapping, but the meaning and updater for `+0x50` remain unknown and its start value is zero. The separate construction-site routine is `FUN_0040ab42`, bound to `PADS`; local `bldinf.txt` declares `CHUG 1 9 1 L`. Its source formula divides global ticks by segment speed plus object `+0x0c`, then adds world-x modulo 23. The remake currently supplies zero for that unresolved object adjustment. A site circle disappears as soon as its runtime item ID is nonzero, even if its sprite asset cannot be drawn.

Offset correction: `FUN_0040bf98` draws the animated `PROD` frame at the item anchor. The `PROD` descriptor's x/y offsets are used only by the conditional threshold overlay drawn after that frame. The remake follows that distinction now; previously it incorrectly displaced the animated frame too.

Construction-site animation now passes the original pad-size subtype (0/1/2 for small/medium/large) into the `FUN_0040ab42` phase formula. `FUN_00461b3b` stores that subtype at the location-record offset consumed as `object[+0x0c]`; the previous renderer incorrectly supplied zero for all site sizes.

Island rendering loads the original `pad.txt`/`bldinf.txt` metadata from `TONE00.COB`, resolves runtime item IDs present on the selected island, and loads their SHP sheets from `TONE01.COB`. It composites the item layers selected by `FUN_0040bf98`; CHUG uses the per-item `+0x3a` counter divided by its declared speed, with loop/ping-pong over the frame range. The session tick now also advances active CONS (`+0x40`, flag `0x004`) and PROD (`+0x42`, flag `0x002`) counters and clears each flag at the threshold obtained by `FUN_00456b8d` / `FUN_00456bd0`; class-2 item 2 now chains CONS into PROD and activates paired bridge markers when PROD completes, while other completion callbacks remain pending. GLYP uses `+0x3c`, INCI uses `+0x3e`, and BARG uses the item double field at `+0x50`. `FUN_0040ab42` remains specific to `PADS`; it is not the generic building animator. Unoccupied `POOL` tone fields and `PADS` retain their own entity renderers, and construction rings are hidden for occupied records. The separate `IWConstruct` item-icon grid remains open.

`test_building_render` covers the `bldinf` animation layers, source counters/flags, offsets, BARG's x87 round-to-even frame mapping, and `CHUG` loop/ping-pong timing; it can validate the actual local text corpus with `test_building_render.exe <pad.txt> <bldinf.txt>`.

World-map rendering and entry now use the original island-access rule: Ghidra's `FUN_00471e66` selects the `SMISLE` frame group `+15` for inaccessible, `+0` for accessible and `+30` for accessible-and-selected islands; `FUN_004711e2` draws a selected island name only when `FUN_0047117d` permits access. The remake uses the selected single-player tribe's access bit for these decisions and entry. Tests cover the frame-group choice. Multiplayer active-mask initialization and island-discovery updates remain unimplemented. Evidence and limitations are documented in the parent [`FUNCTION_GUIDE.md`](../../FUNCTION_GUIDE.md).

The Trade panel now renders the source-described 3×3 offer table with row art from BILDTONE/TONECRYS/MAGCTONE. Left and right cell clicks change each displayed offer by 10 within 0..1000; TradeZERO clears the table and TradeDOIT stores one type-0xb outbound request per nonzero recipient. These requests do not alter resource stocks because multiplayer transport and receipt are not implemented. Evidence and limits are recorded in FUNCTION_GUIDE.md; regression tests are in test_game_trade.

The Diplomacy panel now uses the original DIPLOMA frames, source-derived hover zones, recipient order, captions from `newtext.txt`, and local policy/recipient toggle state. Outbound subtype-10 requests are retained in `GameSession`; multiplayer transport and `FUN_00428191` player banners remain unimplemented. See FUNCTION_GUIDE.md and `test_game_diplomacy` for the evidence and covered cases.
