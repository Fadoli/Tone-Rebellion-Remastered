# Runtime building-item rendering

The construction initializer `FUN_004528ca` does not write the modeled producer cadence at `+0x0c` or BARG double at `+0x50`; placement preserves both values on a reused site (REA `ev_cbf0731fafd218757f4537413f1660e5a9f54ddb78113b8c8fdd2b6fd8bc94b1`).

Bridge completion now grants neighbor-island access to the contributor stored on the marker whose PROD completed, including when construction starts from the opposite endpoint. `FUN_004669bd` reads that marker's `+0x2c`; the prior remake path always read the island-A marker and could grant the wrong player's access (`ev_e249dd4d7d585f32ab8607da5566db19667f43516538d4d908601273c6cf70c1`).

The generic renderer was identified in Ghidra as `FUN_0040bf98`: the remake resolves runtime item IDs through `pad.txt`/`bldinf.txt`, loads each item's SHP, and renders `BASE`, `CHUG`, `GLYP`, `INCI`, `CONS`, `PROD`, conditional `OCCU`, and `BARG` layers. `FUN_00450a71` advances the per-object `+0x3a` CHUG counter only when source flag `0x001` is set for class 0, and advances `+0x3c` GLYP progress while active; `FUN_004528ca` initializes created pads with flags `0x410`, counters zeroed by `FUN_004500c4`, and rate modifier `+0x32 = 1`. These counters and flags are stored per runtime site and advanced by the remake's simulation tick. The tick also advances CONS (`+0x40`, flag `0x004`) and PROD (`+0x42`, flag `0x002`) to their descriptor thresholds. A code-5 delivery to an idle class-2 item 2 starts CONS; its completion starts PROD, and PROD completion activates the paired bridge markers and WORLDPOS edge (`FUN_004669bd`). The completion handler reads the faction slot written at `+0x2c` on the marker that completed production to grant access to the neighbor island. A BUILD BRIDGE command on an idle class-2 marker queues the code-5 delivery through the remake's task flow; REA confirms the packet path in FUN_0042fa0f message 0x3a, while the native control that emits it remains unresolved (REA `ev_ff0149927c5527e42ad97c0ccb0ecff046537edadb26eb9fecf60e1403b49d28`, `ev_ba8f92a6919e9effc29fe5556388fe31c0f95c6bb6cec3f58b14ccedd642103d`, `ev_e249dd4d7d585f32ab8607da5566db19667f43516538d4d908601273c6cf70c1`). Other item-specific completion events and PROD secondary effects remain pending. Ghidra assembly shows `BARG` frame selection uses `(last-first+2) * *(double *)(object+0x50)`, rounds with `FISTP`, offsets from the first frame, then clamps; the remake ports that mapping. For staff buildings `FUN_0045cd75` updates the double to `+0x30 / 250` while a worker trains, then fades it by `0.25` per tick when no trainee is active; the remake ports both updates (`ev_909283391ee942c84efc21a8f5ebd7d5f7`). `FUN_004528ca` leaves this field untouched on placement, so a reused site preserves the native value. The separate construction-site routine is `FUN_0040ab42`, bound to `PADS`; local `bldinf.txt` declares `CHUG 1 9 1 L`. Its source formula divides global ticks by segment speed plus object `+0x0c`, then adds world-x modulo 23. The remake passes the stored pad-size subtype 0/1/2 for that adjustment. A site circle disappears as soon as its runtime item ID is nonzero, even if its sprite asset cannot be drawn.

Offset correction: `FUN_0040bf98` draws the animated `PROD` frame at the item anchor. The `PROD` descriptor's x/y offsets are used only by the conditional threshold overlay drawn after that frame. The remake follows that distinction now; previously it incorrectly displaced the animated frame too.
