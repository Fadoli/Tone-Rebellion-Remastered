# Tone Rebellion remake

An independent, modern C implementation informed by the static analysis documented in the parent `FLOAT_decompilation` directory. Original game files are read-only reference data; the remake does not launch `FLOAT.EXE` or write to the original installation.

## Current milestone

The current implementation contains a portable C11 reader for the observed COB archive directory, parsers for the world map, island locations and construction catalog, an SHP RLE decoder, and a Windows menu executable. The COB API opens archives read-only, validates the fixed-width directory and member ranges, lists entries, and reads a selected member into caller-owned memory. The world parser accepts either an extracted `worldpos.txt` or `data\\worldpos.txt` directly from a COB. SDL3 is not installed in this environment, so the current desktop adapter uses built-in Win32/GDI; the core remains separate so the adapter can later be replaced by SDL3.

Build with CMake and a C11 compiler. `remake_inspect_cob <archive.cob>` lists archive entries. Run `remake_inspect_worlds <path-to-WORLDPOS.TXT>` for an extracted table, or `remake_inspect_worlds --cob <archive.cob> data\\worldpos.txt` to read the member without extracting or modifying the archive. On Windows, the ready-to-launch executable is `ToneRebellion_Remake.exe` in this directory; it reads `C:\\Program Files\\Tone\\TONE01.COB` in read-only mode.

## Build status

Built successfully with CMake and MinGW GCC 6.3.0. The root `ToneRebellion_Remake.exe` is copied from `build/remake_menu.exe`. The COB lister reads 21 entries from `TONE00.COB` and 462 from `TONE01.COB`. The world parser reads `worldpos.txt` both from the local corpus and directly from `TONE01.COB`; counts are `(7, 8)`, `(11, 14)`, and `(15, 22)` for worlds/islands/links. The island parser represents the eleven location tags accepted by original `FUN_00461b3b`, preserving their renderer class/subtype/variant fields. Unknown tags are preserved verbatim and use the fallback site renderer so a new tag cannot prevent opening the whole island. Tone locations are handled as a distinct entity: `POOL` maps to `data\\tone.shp` (40 frames) and declares `CHUG 2 40 3 P` in local `bldinf.txt`; the pool frame mapping follows `FUN_0040bf98`, and runtime items 0 and 5 use their distinct per-record CHUG counter progressions from `FUN_00450a71`; only the wall-clock cadence remains a 33 ms UI-timer approximation. POOL has no PADS-only world-x phase. The explicit `smpad`, `mdpad`, and `lgpad` tags use the 27-frame `PAD.SHP` asset in three nine-frame groups; their phase follows the PADS-specific `FUN_0040ab42` path. `levshld` is not misrendered as a small pad because its specific `SPEARS.SHP` frame mapping remains unresolved. Class-2 bridge sites draw the `BR-TRG01.SHP` base frame; this follows the class-2 `PIT_BridgeTrigger` row in `pad.txt` and its `BR-TRG01` shape, with `bldinf.txt` specifying base frame 1. The 33 ms window timer approximates the original game tick; tribe-visibility flags remain unresolved. The island surface also loads each island's `Ixx-FEAT.SHP` and draws the static feature-sheet layers according to `FUN_0040b345` and each site's `special_value`; triggered layers and altitude haze still need live simulation state. Location layers use the original ascending-Y comparator `FUN_00432940`. Both HZT lookup banks are reconstructed and loaded with the island palette, but scene haze has not been applied to sprites. Class-1 `PIT_Object` and class-3 `PIT_FeatureTrigger` are omitted because local `pad.txt` marks both `noshape`; remaining `special` sites still use inspection markers. `FLOAT.EXE` has not been run.

Regression checks: `ctest --test-dir build --output-on-failure` runs the unit tests, including original RNG, runtime item-rendering, and floater-motion checks. `build/test_pad_catalog.exe <original_content_dir>\\pad.txt` also validates the complete 101-record catalog, original item ordering, and four 16-item player-tribe blocks. `build/test_island_corpus.exe <original_content_dir>` parses every extracted `ISLANDnn.TXT`; `build/test_island_cob.exe <TONE01.COB> <original_content_dir>` parses all island text members and decodes every frame of the SHP assets listed by the local `shapes.txt` manifest, comparing asset paths case-insensitively as Windows does. Non-manifest `.SHP` placeholders such as `l-magton.shp` are excluded. The SHP decoder bounds a frame by its next distinct offset, so shared frame offsets are supported; header-only frames are transparent. Tests also verify that `tone` remains distinct from `PAD_SMALL`, that `TONE.SHP` has 40 frames, that the POOL preview ping-pongs over its locally declared CHUG range, that runtime items draw BASE and follow CHUG loop/ping-pong timing, and that each starting hall SHP has the frame count required by its `BASE` range. CTest targets keep assertions enabled in Release builds.

Tone-pool rendering is layered: `FUN_0040bf98` draws the static `BASE 1 1` frame first, then the animated `CHUG 2 40 3 P` layer from `bldinf.txt`. The remake now composites both frames from `tone.shp`. `FUN_00450a71` gives class-1 runtime ID 0 the counter loop 0..89→0, and ID 5 the distinct 0..125→102 loop; the renderer maps each through `FUN_0040ab05` at speed 3. These are two tracks over the same asset and descriptor, not two separate SHP resources. `POOL` has no `world_x % 23` phase; that belongs to `PADS`'s `FUN_0040ab42`. The 33 ms window timer still substitutes for the original game tick cadence. The POOL sprite is drawn only for the original class-1 ID 0/5 fallback, and is suppressed when that record resolves to a Leviathan building.

# Runtime building-item rendering

The generic renderer was identified in Ghidra as `FUN_0040bf98`: the remake resolves runtime item IDs through `pad.txt`/`bldinf.txt`, loads each item's SHP, and renders `BASE`, `CHUG`, `GLYP`, `INCI`, `CONS`, `PROD`, conditional `OCCU`, and `BARG` layers. `FUN_00450a71` advances the per-object `+0x3a` CHUG counter only when source flag `0x001` is set for class 0, and advances `+0x3c` GLYP progress while active; `FUN_004528ca` initializes created pads with flags `0x410`, counters zeroed by `FUN_004500c4`, and rate modifier `+0x32 = 1`. These counters and flags are stored per runtime site and advanced by the remake's simulation tick. The other source counters (`+0x3e`, `+0x40`, `+0x42`) have renderer support but remain zero until their game events are implemented. Ghidra assembly shows `BARG` frame selection uses `(last-first+2) * *(double *)(object+0x50)`, rounds with `FISTP`, offsets from the first frame, then clamps; the remake ports that mapping, but the meaning and updater for `+0x50` remain unknown and its start value is zero. The 33 ms UI timer approximates the original tick cadence, and this prototype does not yet simulate construction transitions that set flag `0x001`. The separate construction-site routine is `FUN_0040ab42`, bound to `PADS`; local `bldinf.txt` declares `CHUG 1 9 1 L`. Its source formula divides global ticks by segment speed plus object `+0x0c`, then adds world-x modulo 23. The remake currently supplies zero for that unresolved object adjustment. A site circle disappears as soon as its runtime item ID is nonzero, even if its sprite asset cannot be drawn. PROD projectiles/secondary effects and gameplay state transitions remain pending.

Offset correction: `FUN_0040bf98` draws the animated `PROD` frame at the item anchor. The `PROD` descriptor's x/y offsets are used only by the conditional threshold overlay drawn after that frame. The remake follows that distinction now; previously it incorrectly displaced the animated frame too.
