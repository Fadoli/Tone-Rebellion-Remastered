# Tone Rebellion remake

An independent, modern C implementation informed by the static analysis documented in the parent `FLOAT_decompilation` directory. Original game files are read-only reference data; the remake does not launch `FLOAT.EXE` or write to the original installation.

## Current milestone

The current implementation contains a portable C11 reader for the observed COB archive directory, parsers for the world map, island locations and construction catalog, an SHP RLE decoder, and a Windows menu executable. The COB API opens archives read-only, validates the fixed-width directory and member ranges, lists entries, and reads a selected member into caller-owned memory. The world parser accepts either an extracted `worldpos.txt` or `data\\worldpos.txt` directly from a COB. SDL3 is not installed in this environment, so the current desktop adapter uses built-in Win32/GDI; the core remains separate so the adapter can later be replaced by SDL3.

Build with CMake and a C11 compiler. `remake_inspect_cob <archive.cob>` lists archive entries. Run `remake_inspect_worlds <path-to-WORLDPOS.TXT>` for an extracted table, or `remake_inspect_worlds --cob <archive.cob> data\\worldpos.txt` to read the member without extracting or modifying the archive. On Windows, the ready-to-launch executable is `ToneRebellion_Remake.exe` in this directory; it reads `C:\\Program Files\\Tone\\TONE01.COB` in read-only mode.

## Build status

Built successfully with CMake and MinGW GCC 6.3.0. The root `ToneRebellion_Remake.exe` is copied from `build/remake_menu.exe`. The COB lister reads 21 entries from `TONE00.COB` and 462 from `TONE01.COB`. The world parser reads `worldpos.txt` both from the local corpus and directly from `TONE01.COB`; counts are `(7, 8)`, `(11, 14)`, and `(15, 22)` for worlds/islands/links. The island parser represents the eleven location tags accepted by original `FUN_00461b3b`, preserving their renderer class/subtype/variant fields. Unknown tags are preserved verbatim and use the fallback site renderer so a new tag cannot prevent opening the whole island. Tone locations are handled as a distinct entity: `POOL` maps to `data\\tone.shp` (40 frames) and declares `CHUG 2 40 3 P` in local `bldinf.txt`; the pool frame mapping follows `FUN_0040bf98`, and runtime items 0 and 5 use their distinct per-record CHUG counter progressions from `FUN_00450a71`; only the wall-clock cadence remains a 33 ms UI-timer approximation. POOL has no PADS-only world-x phase. The explicit `smpad`, `mdpad`, and `lgpad` tags use the 27-frame `PAD.SHP` asset in three nine-frame groups; their phase follows the PADS-specific `FUN_0040ab42` path. `levshld` is not misrendered as a small pad because its specific `SPEARS.SHP` frame mapping remains unresolved. Class-2 bridge sites draw the `BR-TRG01.SHP` base frame; this follows the class-2 `PIT_BridgeTrigger` row in `pad.txt` and its `BR-TRG01` shape, with `bldinf.txt` specifying base frame 1. The 33 ms window timer approximates the original game tick; tribe-visibility flags remain unresolved. The island surface also loads each island's `Ixx-FEAT.SHP` and draws the static feature-sheet layers according to `FUN_0040b345` and each site's `special_value`; triggered layers and altitude haze still need live simulation state. Location layers use the original ascending-Y comparator `FUN_00432940`. Both HZT lookup banks are reconstructed and loaded with the island palette, but scene haze has not been applied to sprites. Class-1 `PIT_Object` and class-3 `PIT_FeatureTrigger` are omitted because local `pad.txt` marks both `noshape`; remaining `special` sites still use inspection markers. `FLOAT.EXE` has not been run.

Regression checks: `ctest --test-dir build --output-on-failure` runs the twelve unit tests, including original RNG and runtime item-rendering regressions. `build/test_pad_catalog.exe <original_content_dir>\\pad.txt` also validates the complete 101-record catalog, original item ordering, and four 16-item player-tribe blocks. `build/test_island_corpus.exe <original_content_dir>` parses every extracted `ISLANDnn.TXT`; `build/test_island_cob.exe <TONE01.COB> <original_content_dir>` parses all island text members and decodes every frame of the SHP assets listed by the local `shapes.txt` manifest, comparing asset paths case-insensitively as Windows does. Non-manifest `.SHP` placeholders such as `l-magton.shp` are excluded. The SHP decoder bounds a frame by its next distinct offset, so shared frame offsets are supported; header-only frames are transparent. Tests also verify that `tone` remains distinct from `PAD_SMALL`, that `TONE.SHP` has 40 frames, that the POOL preview ping-pongs over its locally declared CHUG range, that runtime items draw BASE and follow CHUG loop/ping-pong timing, and that each starting hall SHP has the frame count required by its `BASE` range. CTest targets keep assertions enabled in Release builds. The latest run passes all twelve CTest tests, including the real local `pad.txt` + `bldinf.txt` catalog check.

Tone-pool rendering is layered: `FUN_0040bf98` draws the static `BASE 1 1` frame first, then the animated `CHUG 2 40 3 P` layer from `bldinf.txt`. The remake now composites both frames from `tone.shp`. `FUN_00450a71` gives class-1 runtime ID 0 the counter loop 0..89→0, and ID 5 the distinct 0..125→102 loop; the renderer maps each through `FUN_0040ab05` at speed 3. These are two tracks over the same asset and descriptor, not two separate SHP resources. `POOL` has no `world_x % 23` phase; that belongs to `PADS`'s `FUN_0040ab42`. The 33 ms window timer still substitutes for the original game tick cadence. The POOL sprite is drawn only for the original class-1 ID 0/5 fallback, and is suppressed when that record resolves to a Leviathan building.

## Menu prototype

The island scene uses the exact pane split in local `windows.txt`: `ISLEVIEW` occupies `(0,0)`–`(639,319)` and `ISLETMP` occupies `(0,320)`–`(639,479)`. It now draws the corresponding `ISLANDnn.SHP` panorama at y=0 and the original `ISLETEMP` template from `isletmp0.shp` at y=320, with site sprite drawing clipped to the upper pane. Location hit testing uses the same scene coordinates. The inspection text is remake UI.

The menu reads and renders original title and new-game sprites from `TONE01.COB` using the observed 6-bit palettes and the RLE structure recovered from `FUN_00404770` / `FUN_00404b74`. It uses the panes in local `windows.txt` for title and setup buttons and the new-game shape families referenced by `FUN_0044ec5d`. The setup screen animates the original glyph and floater frame families and draws the three original orbital rings with the game's LCG for their randomized specks. Begin opens a first world-map view rendered with the original `MAPBACK` and `SMISLE` art and `MAINMAP.PAL`; bridge effects use the observed palette ramp and particle routine, with endpoint interpolation approximated. Static WORLDPOS pairs are not equivalent to active links: Ghidra shows a separate runtime flag table, a handler that sets its counted flags, and a later transition that clears them. The table's loaded-image bytes are zero, but its map-entry runtime state is unresolved. The remake still draws every static pair until that state sequence is understood. Detailed evidence and remaining fidelity gaps are in [GRAPHICS_RECONSTRUCTION.md](GRAPHICS_RECONSTRUCTION.md).

Title-menu and New Game button hit routing now reads the named panes and `SENDMESSAGE` destinations from the parsed `windows.txt` templates; NewGameWin’s special animated-tribe and central-art hit logic remains class-specific. The parser preserves optional pane offsets and other optional descriptor fields. This does not yet instantiate the binary’s full window class hierarchy. The menu uses the original `BGOUTFNT.FNT` bitmap glyph masks and reads contextual French help text from `tonehelp.txt` in `TONE00.COB`. On the title screen, hovering over a menu control shows its help text and alternate button frame. On New Game, hovering over a tribe, world-size, difficulty, exit, or begin control displays the corresponding short localized caption from `NEWGAME0`–`NEWGAME7` in `gamey.txt`, centered in the lower strip. It also reads the paired tribe lore entries from `newgame.txt` and shapes/justifies each line along the circular center opening, following `FUN_00428baa` and its `FUN_0044e613` bounds callback. The current text bottom anchor remains a remake parameter while the original text-height call is unresolved. Clicking any animated tribe glyph changes the tribe and lore. Clicking the center art changes difficulty or world size in the small hit regions recovered from `FUN_0044e4f8` and `FUN_0044ebea`; the footer buttons remain available. It avoids clearing the visible viewport between frames, advances the floater at the original half-rate tick cadence, and plays the archive's `BUTTON.WAV` on mouse clicks. Music remains unimplemented.

Keyboard: Enter advances from title to setup, setup to the map, and the map to the selected island; with no map selection, it opens the chosen tribe's homeworld. N opens setup, Escape returns one screen, Left/Right change world size on setup/map and scroll the island panorama, D cycles difficulty, and 1–4 select tribes.

The world-size and five-value difficulty cycles match the `FUN_00448e5a` master handler; clicking the animated tribe glyphs follows `FUN_0044e4f8` and the tribe message path. On the map, hovering opaque island pixels displays the corresponding name from `names.txt`; clicking once selects an island and Enter or a second click opens it. Hit bounds and reverse draw-order hit testing follow `FUN_00405e11` and `FUN_00472013`. The island view loads the selected `ISLANDnn.SHP` panorama and palette, retains its `ISLANDnn.HZT`, parses `ISLANDnn.TXT` coordinates, and allows horizontal scrolling and location selection. `tone` locations render as animated Tone pools from `TONE.SHP`; the `smpad`, `mdpad`, and `lgpad` locations use their respective animation groups in `PAD.SHP`. Static feature layers use the island-specific `Ixx-FEAT.SHP`. The two original HZT lookup banks are reconstructed and loaded with the island palette; triggered feature states, scene haze application, other site sprites, game simulation, construction placement, and dynamic discovery remain unimplemented. Other site dots and the footer are remake interaction aids. Clicking an empty constructible pad opens the `IWConstruct` grid using the panes and templates from `windows.txt`; hovering an item updates the matching `IWConstructInfo` pane, and `BuildCycle` changes pages. The grid uses the original ordered candidates and per-tribe item sprites. The click-to-build gameplay event, placement, and resource checks are not wired yet; clicking an entry only updates its preview. The Load screen uses the original `LOADSAV0.SHP` artwork. It scans the eight `%02d.sav` slots read-only and applies the Ghidra-observed 0x80-byte header, `1.16` version prefix, and `0x378b8` marker. Clicking an empty slot returns to the title screen, as the original handler does; valid files get a clear notice because full save restoration is not implemented yet. The installed eight `.SAV` files are all one-byte placeholders, so none are loadable. Resume is not connected to savegame restoration. The 640×480 surface stays 4:3 when resized, and mouse hit testing uses the letterboxed viewport.

The generic descriptor loader is grounded in `FUN_0046cd22` and the `windows.txt` records; it preserves the two extra `PANE` values seen on stockpile controls, while their runtime interpretation remains unverified. The portable `IWConstruct` model captures the observed four-column hover/click selection, page cycling, selection messages, the `IWConstructInfo` selected-item message, and the `BuildCycle` visibility threshold (`item_count > 4`) from `FUN_0043aa9f`, `FUN_0043ad79`, `FUN_0043acea`, and `FUN_0043b2d1`. It also ports `FUN_0045f121`'s ordered eight-item candidate filter. ## Initial game-world setup

The portable core has `game_start_assign_locations`, grounded in `FUN_0046466f`: normal mode assigns the four player slots to island indices 0–3, chooses a class-1 marker (`tone`) by its source-row ordinal (first for even slots, fourth for odd slots), then selects the nearest eligible class-0 location using the original Chebyshev metric from `FUN_004672a6`. Equal distances keep the first source row. It also reproduces the horizontal camera bounds, the raw initial pad argument `0x2a`, and four floater creation parameters at the marker. `FUN_004641de` resolves that argument per player as `0x2a + 16 * player`, yielding `p-hall`, `s-hall`, `m-hall` and `l-hall`; `game_session.c` now stores these resolved runtime item IDs. Alternate mode's island and marker-index rule is implemented as it appears in the pseudocode.

`tone_rng.c` implements the shared 15-bit LCG from `FUN_00474b90` and bounded scaling from `FUN_00467260` (`random × range / 32768`, truncating toward zero). The Win32 menu's visual randomness now uses this core helper. `tone_rng_unit` checks the observed output sequence and bound scaling.

`game_start_distribute_tones` ports marker/item selection from `FUN_00464b9e`/`FUN_004535e4`: first/last markers on islands 0–3, optional opposite marker in alternate mode, random selection from the first five markers on later islands, and IDs 6–9 constrained by two shape-ID tables. Its balance calculation follows the runtime reset in `FUN_004500c4`: parsed `+0x10` values persist only on class 3; prior placements in the current distribution also count. The home-island index corresponding to `DAT_006136b0 - 1` remains an explicit parameter because the global's runtime initialization is unresolved.

`game_session_initialize` in `src/core/game_session.c` builds mutable runtime records for an entire selected world. It applies per-player hall item IDs, floater starts, marker item placements, class-2 state `2`, class-2-to-bridge neighbor matches from `FUN_00461859`, and both class-0 assignment loops visible in `FUN_004637fc` (`bridge_count` sites with value `+0x24 = 5`, then two shape-derived assignments per island except the last). The Win32 New Game action reads every island layout in the selected world from `TONE01.COB` and initializes this session before opening the map. The island view resolves runtime items through `pad.txt` and `bldinf.txt`, loads their SHP sheets, and composites the data-driven layers selected by `FUN_0040bf98`. The source animation fields are preserved per site; CHUG/GLYP tick from `FUN_00450a71`, while other counters await the game transitions that update them. `FUN_0040ab42` is not used as a generic building animator because `FUN_0046303b` binds it to `PADS`. Initial idle floaters use the tribe-specific body/leg sheets listed in `fltinf.txt` and `shapes.txt`; `FUN_0042704b` plus `shapeinf.txt` ground body frame 0 and legs hover frames 0–15. The remake advances that hover cycle with its 33 ms timer, while the original in-game phase remains unresolved. It also uses runtime bridge matches and reports the selected record's current item/owner/auxiliary values. An integration check builds world 0 from local `WORLDPOS.TXT` plus its original `ISLANDnn.TXT` records; it resolves seven islands, eight bridge sites and twenty class-0 assignments. `DAT_006136b0` is unresolved, so the Win32 path currently supplies explicit home-island index 0; it does not infer this from the tribe selection. The `DAT_0049c99c` branch remains a configuration flag, with random assignment disabled in the UI. Startup IDs `0x17`–`0x19`, exact whole-startup RNG stream, full entity side effects, and `FUN_00460460` recalculation remain unported. See `../world_start_distribution.md` for evidence and limits. CTest currently has twelve passing unit tests.
# Runtime building-item rendering

The generic renderer was identified in Ghidra as `FUN_0040bf98`: the remake resolves runtime item IDs through `pad.txt`/`bldinf.txt`, loads each item's SHP, and renders `BASE`, `CHUG`, `GLYP`, `INCI`, `CONS`, `PROD`, conditional `OCCU`, and `BARG` layers. `FUN_00450a71` advances the per-object `+0x3a` CHUG counter only when source flag `0x001` is set for class 0, and advances `+0x3c` GLYP progress while active; `FUN_004528ca` initializes created pads with flags `0x410`, counters zeroed by `FUN_004500c4`, and rate modifier `+0x32 = 1`. These counters and flags are stored per runtime site and advanced by the remake's simulation tick. The other source counters (`+0x3e`, `+0x40`, `+0x42`) have renderer support but remain zero until their game events are implemented. Ghidra assembly shows `BARG` frame selection uses `(last-first+2) * *(double *)(object+0x50)`, rounds with `FISTP`, offsets from the first frame, then clamps; the remake ports that mapping, but the meaning and updater for `+0x50` remain unknown and its start value is zero. The 33 ms UI timer approximates the original tick cadence, and this prototype does not yet simulate construction transitions that set flag `0x001`. The separate construction-site routine is `FUN_0040ab42`, bound to `PADS`; local `bldinf.txt` declares `CHUG 1 9 1 L`. Its source formula divides global ticks by segment speed plus object `+0x0c`, then adds world-x modulo 23. The remake currently supplies zero for that unresolved object adjustment. A site circle disappears as soon as its runtime item ID is nonzero, even if its sprite asset cannot be drawn. PROD projectiles/secondary effects and gameplay state transitions remain pending.

Offset correction: `FUN_0040bf98` draws the animated `PROD` frame at the item anchor. The `PROD` descriptor's x/y offsets are used only by the conditional threshold overlay drawn after that frame. The remake follows that distinction now; previously it incorrectly displaced the animated frame too.

Construction-site animation now passes the original pad-size subtype (0/1/2 for small/medium/large) into the `FUN_0040ab42` phase formula. `FUN_00461b3b` stores that subtype at the location-record offset consumed as `object[+0x0c]`; the previous renderer incorrectly supplied zero for all site sizes.

Island rendering loads the original `pad.txt`/`bldinf.txt` metadata from `TONE00.COB`, resolves runtime item IDs present on the selected island, and loads their SHP sheets from `TONE01.COB`. It composites the item layers selected by `FUN_0040bf98`; CHUG uses the per-item `+0x3a` counter divided by its declared speed, with loop/ping-pong over the frame range. The session tick now also advances active CONS (`+0x40`, flag `0x004`) and PROD (`+0x42`, flag `0x002`) counters and clears each flag at the threshold obtained by `FUN_00456b8d` / `FUN_00456bd0`; item-specific completion events are not yet simulated. GLYP uses `+0x3c`, INCI uses `+0x3e`, and BARG uses the item double field at `+0x50`. `FUN_0040ab42` remains specific to `PADS`; it is not the generic building animator. Unoccupied `POOL` tone fields and `PADS` retain their own entity renderers, and construction rings are hidden for occupied records. The separate `IWConstruct` item-icon grid remains open.
