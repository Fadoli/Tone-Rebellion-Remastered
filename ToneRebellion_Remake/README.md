# Tone Rebellion remake

An independent, modern C implementation informed by the static analysis documented in the parent `FLOAT_decompilation` directory. Original game files are read-only reference data; the remake does not launch `FLOAT.EXE` or write to the original installation.

## Current milestone

The current implementation contains a portable C11 reader for the observed COB archive directory, parsers for the world map and island locations, an SHP RLE decoder, and a Windows menu executable. The COB API opens archives read-only, validates the fixed-width directory and member ranges, lists entries, and reads a selected member into caller-owned memory. The world parser accepts either an extracted `worldpos.txt` or `data\\worldpos.txt` directly from a COB. SDL3 is not installed in this environment, so the current desktop adapter uses built-in Win32/GDI; the core remains separate so the adapter can later be replaced by SDL3.

Build with CMake and a C11 compiler. `remake_inspect_cob <archive.cob>` lists archive entries. Run `remake_inspect_worlds <path-to-WORLDPOS.TXT>` for an extracted table, or `remake_inspect_worlds --cob <archive.cob> data\\worldpos.txt` to read the member without extracting or modifying the archive. On Windows, the ready-to-launch executable is `ToneRebellion_Remake.exe` in this directory; it reads `C:\\Program Files\\Tone\\TONE01.COB` in read-only mode.

## Menu prototype

The menu reads and renders original title and new-game sprites from `TONE01.COB` using the observed 6-bit palettes and the RLE structure recovered from `FUN_00404770` / `FUN_00404b74`. It uses the panes in local `windows.txt` for title and setup buttons and the new-game shape families referenced by `FUN_0044ec5d`. The setup screen animates the original glyph and floater frame families and draws the three original orbital rings with the game's LCG for their randomized specks. Begin opens a first world-map view rendered with the original `MAPBACK` and `SMISLE` art and `MAINMAP.PAL`; WORLDPOS bridge pairs now use the observed palette ramp and particle effect, with endpoint interpolation approximated. Which links are active in a real game state is not resolved yet. Detailed evidence and remaining fidelity gaps are in [GRAPHICS_RECONSTRUCTION.md](GRAPHICS_RECONSTRUCTION.md).

The menu uses the original `BGOUTFNT.FNT` bitmap glyph masks and reads contextual French help text from `tonehelp.txt` in `TONE00.COB`. On the title screen, hovering over a menu control shows its help text and alternate button frame. On New Game, hovering over a tribe, world-size, difficulty, exit, or begin control displays the corresponding short localized caption from `NEWGAME0`–`NEWGAME7` in `gamey.txt`, centered in the lower strip. It also reads paired tribe lore entries from `newgame.txt` and displays the selected tribe's two descriptions in narrow side columns. Clicking any animated tribe glyph changes the tribe and lore. Clicking the center art changes difficulty or world size in the small hit regions recovered from `FUN_0044e4f8` and `FUN_0044ebea`; the footer buttons remain available. It avoids clearing the visible viewport between frames, advances the floater at the original half-rate tick cadence, and plays the archive's `BUTTON.WAV` on mouse clicks. Music remains unimplemented.

Keyboard: Enter advances from title to setup, setup to the map, and the map to the selected island; with no map selection, it opens the chosen tribe's homeworld. N opens setup, Escape returns one screen, Left/Right change world size on setup/map and scroll the island panorama, D cycles difficulty, and 1–4 select tribes. The world-size and five-value difficulty cycles match the `FUN_00448e5a` master handler; clicking the animated tribe glyphs follows `FUN_0044e4f8` and the tribe message path. On the map, hovering opaque island pixels displays the corresponding name from `names.txt`; clicking once selects an island and Enter or a second click opens it. Hit bounds and reverse draw-order hit testing follow `FUN_00405e11` and `FUN_00472013`. The island view loads the selected `ISLANDnn.SHP` panorama and palette, retains its `ISLANDnn.HZT`, parses `ISLANDnn.TXT` coordinates, and allows horizontal scrolling and location selection. The three pad size classes are drawn with `solidpad.shp` at the source coordinates. Other site dots and the footer are remake interaction aids; HZT palette remapping, other site sprites, simulation, construction, and dynamic discovery are not implemented yet. The Load screen uses the original `LOADSAV0.SHP` artwork. It scans the eight `%02d.sav` slots read-only and applies the Ghidra-observed 0x80-byte header, `1.16` version prefix, and `0x378b8` marker. Clicking an empty slot returns to the title screen, as the original handler does; valid files get a clear notice because full save restoration is not implemented yet. The installed eight `.SAV` files are all one-byte placeholders, so none are loadable. Resume is not connected to savegame restoration. The 640×480 surface stays 4:3 when resized, and mouse hit testing uses the letterboxed viewport.

The directory layout and fixed widths come from static bytes plus the Ghidra COB loader (`FUN_0040ff5b`); C error handling, API shape, and strict validation are remake implementation choices, not recovered source. Offsets are required to increase strictly because that is true of both supplied archives. Member lookup is exact and case-sensitive. No assumptions are made about game-rule meanings beyond the format labels recorded in `FLOAT_decompilation` documentation.
